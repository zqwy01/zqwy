# Лабиринт сознаний · Zemic

Браузерный прототип о Zemic, который уже находится внутри Лабиринта сознаний. Это статическое приложение на HTML, CSS и JavaScript: без сборщика, backend, базы данных и Node.js на стороне игрока.

Мир Лабиринта создаётся лениво по чанкам, поэтому он не заканчивается на стартовом участке и не требует заранее построенной карты. Новый запуск получает новый случайный seed, а сохранённый мир продолжается с тем же seed.

## Быстрый запуск

1. Откройте `index.html` в современном браузере.
2. Либо запустите статическую раздачу из корня проекта `files/` (на две директории выше), чтобы был доступен общий архив музыки, и откройте `http://127.0.0.1:8000/games/zqwy/`:

```bash
cd ../..
python3 -m http.server 8000
```

Для GitHub Pages публикуется структура `files/` целиком: игра лежит в `games/zqwy/`, а музыка — в общем архиве `src/tracks/`, на который игра ссылается относительным путём. Сборка не требуется.

`localStorage` может быть ограничен при открытии через `file://` или в приватном режиме. Игра в этом случае продолжает работать, но прогресс между перезагрузками может не сохраняться.

## Управление

| Действие | Клавиатура | Сенсорный экран |
| --- | --- | --- |
| Движение в восьми направлениях | `W` `A` `S` `D` / стрелки | экранный D-pad |
| Идти к точке | ЛКМ по миру | касание мира |
| Следовать за курсором | удержание ЛКМ | удержание касания |
| Взаимодействие | `E` | кнопка действия `✦` |
| Команда терминала | `Enter` | поле ввода |
| История команд | `↑` / `↓` в поле ввода, команда `история` | — |
| Вернуться / закрыть представление | `Esc` | кнопки `×`, «← к столу» |
| Разделитель игры и терминала | `↑` / `↓` / `Home` при фокусе на разделителе | перетаскивание за полосу |
| Масштаб стола | колесо мыши | щипок двумя пальцами, кнопки `−` / `100%` / `+` |
| Двигать стол | ЛКМ по пустому месту | перетаскивание пустого места |
| Закрыть печать в испытании | `Space` | кнопка `✦` |

По умолчанию не назначено ни одной «быстрой» клавиши для инвентаря, карты, стола, осмотра или остановки. Такие привязки создаются игроком на столе: одна клавиша может запускать несколько связанных целей. Базовыми остаются только движение, `E`, `Enter`, `Space` в испытании и `Esc` для закрытия представлений.

Открытые вкладки терминала — инвентарь, карта, сюжет, стол, настройки, плеер и настройки шрифта — не блокируют управление: Zemic можно вести клавишами, ЛКМ или геймпадом, не закрывая представление. Исключения — испытание и аркадный автомат: это отдельные режимы, которые приостанавливают мир. `Esc` закрывает активную вкладку и возвращает основную.

Подсказка по управлению не занимает отдельную полосу под экраном: при запуске одним системным сообщением в лог выводятся версия ядра, время загрузки мира, число комнат и чанков, seed и полная справка по управлению. Отдельных визуальных баннеров и подсказок на игровом холсте нет.

В игре используется собственный курсор: системный указатель над игровым холстом скрыт, а позицию показывает кольцо с точкой. Оно реагирует на нажатие ЛКМ. На кнопках интерфейса остаётся обычный курсор.

Движение из терминала плавное и длится по времени: `идти вниз` — одна секунда, `идти вниз 10` — десять секунд.

Ходьба по ЛКМ использует поиск пути по проходимым клеткам: Zemic обходит стены и препятствия, а не идёт напрямую сквозь них. Если точка недоступна, выбирается ближайшая достижимая клетка. Путь начинается из текущей позиции героя и заканчивается у самого курсора, поэтому при удержании ЛКМ нет рывков назад к центру клетки и цель не «прилипает» к тайлу. При удержании маршрут пересчитывается только тогда, когда курсор переходит на другую целевую клетку.

## Команды и помощь

Терминал понимает команды: `помоги`, `привет`, `ты куда пропал`, `подойди`, `идти вверх` / `идти вниз` / `идти влево` / `идти вправо` (можно с длительностью), `стоп`, `осмотреться`, `посмотреть`, `сюжет`, `инвентарь`, `рюкзак`, `карта`, `стол`, `пометить`, `очаровать`, `настройки`, `логгирование`, `плеер`, `аркада`, `история`, `язык`, `сохранить`, `загрузить`, `экспорт`, `очисти`, `новая игра`. В Зеркальном зале работают `отражение` (синонимы `зеркало`, `вишня`), `ответить я` / `ответить ты` / `ответить никто` и `прости`. `музыка` остаётся синонимом `плеер`, `автомат` и `arcade` — синонимы `аркада`, а `рюкзак` — это отчёт о вещи и её состоянии, не открытие инвентаря. Короткие формы `вверх`/`вниз`/`влево`/`вправо` и английские псевдонимы (`help`, `walk down`, `stop`, `history`, `language`, `save`, `load`, `export`, `inventory`, `backpack`, `player` и другие) тоже работают. Для немецкого доступны `hilfe`, `laufen oben`, `halt`, `einstellungen`, `speichern`, `laden`, `musik`, `sprache`, `inventar`, `rucksack` и другие псевдонимы.

`помоги` выводит только открытые группы команд:

- `основное` — терминал и ориентирование;
- `сюжет` — ветвь истории, находки и цель;
- `движение` — шаги по времени и остановка;
- `инвентарь` — ячейки, граф предметов и связи; `рюкзак` — отчёт о вещи и её состоянии;
- `карта` — путь и метки;
- `стол` — рабочая поверхность и клавиши;
- `карты` — способности;
- `логгирование` — запись шагов, действий, команд и источников;
- `терминал` — настройки, язык и история команд;
- `данные` — сохранение, загрузка и экспорт мира;
- `плеер` — проигрыватель, кассеты, перемотка, громкость и скорость; `музыка` — синоним;
- `аркада` — автомат, кассеты игрока и ритм-каталог; `автомат` — синоним.

`помоги движение` раскрывает одну группу. Закрытая группа вообще не попадает в список: пока рюкзак, карта или стол не открыты сюжетом, `помоги` о них не упоминает. Те же открытые группы используются в панели добавления на столе, чтобы не выводить все команды сразу.

Команда `история` выводит буфер введённых команд — тот же, который листается клавишами `↑` / `↓`. `язык английский` / `язык немецкий` / `язык русский` переключает интерфейс и терминал; в английском режиме доступны английские псевдонимы команд, в немецком — немецкие. Немецкая локализация — частичный оверлей: интерфейс, команды, сюжетные сцены и описания переведены, редкие служебные фрагменты могут оставаться на английском.

Автодополнение работает как прогноз прямо в поле ввода: известная часть команды остаётся обычным текстом, а вероятное продолжение показывается полупрозрачным текстом сразу после курсора. Отдельного столбца или списка подсказок в терминале нет. `Tab` принимает продолжение, `Esc` скрывает его, `↑` / `↓` по-прежнему листают историю. В подсказку попадают направления и длительность для `идти`, значения для `язык` и `логгирование`, открытые группы для `помоги`, разделы `настройки`, действия `плеер` / `музыка` / `аркада` и команды из истории.

Команда `новая игра` удаляет сохранение, создаёт новый случайный seed, заново строит стартовый чанк и сбрасывает открытия, предметы, метки и элементы стола. Seed нового мира выводится в лог. Сохранение, загрузка и экспорт мира доступны также кнопками в `настройки` → «Данные».

## Запись действий

«Запись действий» — это фильтр полезной текстовой информации, а не отдельная система слежки. Например, категория «движение» записывает шаги персонажа. Команда `логгирование` управляет записью событий в терминал. По умолчанию лог выключен, но категории уже настроены:

- `логгирование вкл` / `логгирование выкл` — весь лог;
- `логгирование всё` / `логгирование ничего` — включить или выключить все категории;
- `логгирование движение` — шаги персонажа;
- `логгирование действия` — взаимодействия и предметы;
- `логгирование команды` — введённые и связанные команды;
- `логгирование терминал` — сообщения самого терминала;
- `логгирование сцены` — сюжетные сцены и реплики;
- `логгирование система` — системные сообщения;
- `логгирование мир` — загрузка мира, чанки и seed.

При включённом логе шаг появляется в терминале строкой с меткой «шаг». Категории можно переключать и в `настройки` → «Терминал». Настройки записи сохраняются в `localStorage` вместе с остальными настройками терминала.

## Сюжет

Команда `сюжет` открывает отдельное представление в терминале — только для чтения. Оно оформлено как стол: карточки этапов расположены колонками по глубине ветви, а связи нарисованы изогнутыми стрелками, поэтому схему можно читать как сюжетный граф. Граф не блокирует игру: пока он открыт, Zemic можно вести клавишами или ЛКМ, а `Esc` возвращает основную вкладку терминала.

В представлении показаны:

- всё дерево этапов с состояниями «пройдено», «сейчас» и «закрыто»;
- побочные ветви, включая возвращение после гибели.

Отдельного контейнера с описанием текущего этапа нет: остаётся только полотно графа. Карточки этапов можно перетаскивать левой кнопкой мыши, а пустое полотно — панорамировать той же кнопкой. Позиции карточек и сдвиг полотна сохраняются в текущей сессии и сбрасываются при новой игре.

В графе нет кнопок перехода: это карта пути, а не меню телепортации. Сюжетные сцены по-прежнему выводятся в общий лог терминала.

## Прогрессия и открытия

В начале доступны только базовые команды и движение. Рюкзак, карта и стол открываются по истории:

- **Скрижаль** открывает команды `инвентарь` и `рюкзак`, а также `стол` — при первом входе в комнату или по действию `E` рядом со Скрижалью.
- **Обрывок карты** в Кладовой открывает `карту`; без него карта отвечает, что пока недоступна.
- `пометить` требует угольный мелок, а `очаровать` — карту «Очарование».

Закрытые команды не выполняются: терминал отвечает подсказкой об открытии. В `помоги` и в панели стола они не показываются, пока соответствующая группа не откроется сюжетом. Кнопки рюкзака, карты, стола и способностей также скрыты до открытия. Открытия входят в сохранение.

## Интерфейс: игра и терминал

Экран разделён на две основные области. Верхняя — только изображение игры: мир, виньетка, сенсорное управление и сцена испытания. В ней нет заголовков комнат, HUD, подсказок, уведомлений и кнопок систем. Нижняя — терминал, внутри которого живут все тексты и системные представления:

- основной лог команд, строка контекста «рядом: …» и поле ввода с подсказкой «Введите команду и нажмите отправить»;
- инвентарь: ячейки, граф предметов и связей, перетаскивание узлов по всей канве;
- карта участка 7×5 комнат, которая следует за игроком;
- стол с инструментами, масштабом, панорамированием, клавишами, предметами и командами; с устройством «мышь» в списке схем управления и закрытием через крестик `×`;
- полный просмотр карты с возвратом в инвентарь или на стол;
- общие настройки: язык, шрифт, плеер и данные;
- отдельное представление настроек шрифта: общий размер и размеры по разделам;
- встроенный плеер: пауза `▶` / `❚❚`, стоп `■` с возвратом в начало, перемотка, громкость, волновая дорожка, скорость 0.5×–2× и библиотека альбомов и дорожек;
- граф сюжета;
- статус испытания.

Сюжетные сцены, гибель и результат испытания не открывают отдельных экранов и не требуют кнопки «Дальше»: их текст добавляется прямо в лог терминала. Реплики помечаются говорящим (`КЛАДОВАЯ`, `КРУГ`, `СКРИЖАЛЬ`, `ЛАБИРИНТ`), системные сообщения, ответы терминала и записи лога используют единый служебный цвет, введённые команды — метку `Zemic:`. Строка «рядом: коснуться Скрижали · E» выводится в терминале; на игровом холсте подсказок нет.

### Правила терминала

Эти правила обязательны для всех будущих патчей:

- в терминале нет часов, текущего времени и меток времени у сообщений — это поток текста, а не журнал;
- над терминалом нет строки состояния и подписи «терминал»; лог начинается сразу с сообщений;
- команда `часы` и её псевдонимы не возвращаются, как и отдельная группа команд для времени.

### Адаптивная компоновка

Игра и терминал занимают весь viewport, а не вписываются в жёсткое соотношение 9:16. Поддерживаются и вертикальный 9:16, и широкий 16:9: кадр нигде не обрезается и не ужимается в чужой прямоугольник. На узком экране области складываются вертикально, на широком игровая область расширяется по горизонтали. Камера при этом остаётся строго центрирована на Zemic. Safe-area-отступы учитываются.

Вместо обрезки кадра размер тайла выбирается так, чтобы в игровом окне всегда оставалось не меньше `14.5` клеток по ширине и `13.2` по высоте: `tile = min(ширина / 14.5, высота / 13.2)` с нижним пределом `11 px` и верхним `46 px`. Поэтому в портрете видно больше клеток по вертикали, в ландшафте — по горизонтали, а играбельная дистанция не пропадает. Сцена получает класс `portrait` или `landscape`; CSS-раскладка боя и погони подстраивается под него.

Проверка пропорций осталась только как информационная: допустимый диапазон — примерно от `0.4:1` до `3.4:1`. Если окно выходит за него, в терминал один раз выводится текстовое сообщение с фактическим соотношением. Сцена при этом всё равно не обрезается. Отдельного визуального баннера или предупреждения на холсте нет.

### Шрифты и типографика

Все размеры текста собраны в отдельном модуле `js/fonts.js` и в токенах `--fs-micro` … `--fs-h1`, которые считаются от одной переменной `--type-unit`. Поэтому кнопки, подписи, терминал и стол больше не расходятся по размеру. Глобальный размер шрифта задаётся числом, ползунком и пресетами 12/14/16/18 px в диапазоне 10–24 px; минимальные подписи при этом остаются читаемыми. Размеры шрифта вынесены в отдельный раздел настроек «Настройки: шрифт», куда ведёт кнопка из общих настроек. Внутри него можно отдельно переопределить терминал и стол. Переопределение `0` означает «наследовать общий размер»; кнопка «авто» сбрасывает его. Значения хранятся вместе с остальными настройками терминала.

Заголовки настроек оформлены иерархией: «Настройки» — H1, разделы («Язык», «Шрифт», «Музыка», «Данные») — H2. Подразделы «Настройки: терминал», «Настройки: шрифт» и «Музыка» открываются из общего раздела и возвращают в него по кнопке «← общие настройки».

### Разделитель

Между областями есть разделитель. Его можно перетаскивать мышью, пальцем или клавишами `↑`/`↓`; `Home` возвращает пропорцию по умолчанию. Минимальная высота игровой области — 170 px, терминала — 150 px, поэтому ни одна сторона не может исчезнуть. Пропорция сохраняется в `localStorage` под ключом `zqwy.labyrinth.split.v1`. По умолчанию в ландшафте игре достаётся 56% высоты, а в портрете — 60%: так на вертикальном экране остаётся достаточно проходов впереди. При открытии систем терминал при необходимости расширяется до минимальной доли, чтобы содержимое оставалось читаемым.

### Стол

Стол открывается прямо в терминале и не перекрывает игру отдельным окном. Заголовок — «Стол». На нём свободно размещаются элементы: предметы, команды и отдельные клавиши. Короткое нажатие на предмет или команду выполняет её; перетаскивание меняет положение; кнопка `×` убирает элемент. Кнопка добавления обозначена просто символом `+`, а режим связи — стрелкой `→`.

Элементы можно перетаскивать в любую точку рабочей поверхности, вплоть до самых краёв. Внутренних отступов и ограничений положения больше нет: и при перетаскивании, и при загрузке макета координаты ограничены только диапазоном `0…1`, а не безопасной серединой.

Сетка стола непрерывна во все стороны: она не заканчивается на границах рабочей области, а прокручивается и масштабируется вместе с рабочей поверхностью. Элементы можно уводить далеко за пределы стартового экрана.

Клавиша — самостоятельный элемент. У неё есть код (`T`, `F`, `Space` и т. д.) и список ссылок на цели. Связь видна как настоящая линия со стрелкой, идущая от клавиши к цели; на линии подписана клавиша. Одна клавиша может быть связана с несколькими командами и предметами и запускает их по очереди.

Порядок работы:

1. Нажмите `+` и выберите «клавиша» или нажмите клавишу на интерактивной схеме.
2. Клавиша сразу появляется на столе.
3. Включите `→` («связать»), выберите клавишу, затем нажимайте цели, чтобы добавить или убрать связь.
4. Выключите `→`. Пока стол открыт, связанные клавиши работают; в основной вкладке работают те, что не заняты базовым управлением.

Схема «клавиши» — интерактивная визуализация клавиатуры: нажатие на кнопку клавиши сразу добавляет её на стол, а у уже добавленных клавиш показывает число связей и позволяет выбрать их в режиме `→`. Это не декоративная картинка.

Масштаб стола регулируется колесом, щипком и кнопками в диапазоне 18–320%; ЛКМ по пустому месту двигает рабочую поверхность. Кнопка `100%` сбрасывает и масштаб, и положение. Элементы, связи и привязки сохраняются в `localStorage`.

## Мир и генерация

Мир бесконечен и строится лениво. Стартовый чанк `(0,0)` создаётся сразу, потому что в нём находятся Скрижаль, сюжетные комнаты и точка появления. Остальные чанки появляются, когда игрок или карта приближаются к ним.

- Чанк — сетка комнат `5×5`, зазор между комнатами — 6 тайлов.
- Комната больше не фиксированная: её размер детерминирован для клетки и seed и меняется от крошечной (`7×6`) до огромной (`39×31`). Большинство залов небольшие, но редкие огромные залы специально оставлены — в них помещается титанобоа и есть где развернуться бою.
- Форма зала тоже выбирается по seed: прямоугольник, скошенные углы, овал, «песочные часы», крест, Г-образная ниша или неровная пещера. Сюжетные залы остаются прямоугольными, а зал титанобоа — намеренно огромная пещера. Маска задаётся внутри комнаты, поэтому внешняя стена остаётся целой, а двери прорезаются до настоящего пола.
- Размер чанка в тайлах — `225×185`.
- Структура каждого чанка детерминирована парой `seed + координаты чанка`, поэтому один и тот же мир восстанавливается из сохранения, а разные seed дают разные лабиринты.
- Внутри чанка комнаты соединяются связным «расплетённым» графом с петлями; на границах чанков есть проходы. Тупики у обычных комнат убираются, у Круга Очарования остаётся ровно один вход.
- Проходы в стенах комнат имеют ширину от 1 до 12 тайлов и располагаются в произвольном месте стены, а не строго по центру стороны. Поэтому лабиринт получается менее линейным.
- Сюжетные комнаты закреплены в домашнем чанке: Скрижаль, Слепой зал, Низкий свод, Круг Очарования, Кладовая, Тихий перекрёсток и Зеркальный зал. У первой процедурной сюжетной комнаты шанс появления — 25%, у последующих ниже.
- Фоновые комнаты получают имена, колонны и находки из того же seed; игрок физически переходит между комнатами и может возвращаться.

Карта терминала показывает окно 7×5 комнат вокруг текущей. Поскольку мир не имеет границы, окно переезжает вместе с игроком, а не изображает весь Лабиринт целиком.

### Схватки в Лабиринте

Zemic — аксолотль, и схватки происходят прямо в том зале, где он стоит. Отдельной мини-игры, второй арены, второго холста и отдельной вкладки терминала нет: снаряды, рывок, зонт и урон считаются в тех же мировых клетках, что и обычная ходьба. Сверху остаётся только компактная панель состояния.

- Комнаты `beetle` и `umbrella` начинаются сами при входе, без согласия игрока и без кнопки подтверждения. Повторяемая встреча `belzebufo` тоже не спрашивает согласия, но срабатывает только у плёса в центре её зала, а не на пороге.
- Бой длится ровно столько, сколько звучит его трек (`durationMode: 'track'`): таймер в HUD идёт в формате `мм:сс` и совпадает с музыкой, а не обрывается на половине. Предохранитель `C.battle.durationCap` (по умолчанию `null`) может ограничить затянувшуюся схватку числом секунд.
- Цель — продержаться до конца трека, а не снять здоровье противника: у врагов нет полосы HP, зато есть вода, течение и плотный поток снарядов.
- Враг не стоит в центре зала. У каждой схватки есть преследователь (`encounter.enemy`): жук, тёмный зонт или бельзебуфо. Он ползёт за Zemic по всему миру теми же шагами, что и титанобоа, стреляет на ходу из своей позиции и наносит урон касанием. Убежать и отсидеться не выйдет — можно только уходить из-под удара до конца боя. Скорость задаётся жанром (`enemySpeed`) или `encounter.enemySpeed`.
- Залпы не берутся из пустоты: перед каждой волной враг «заряжается» (`C.battle.telegraph`), вокруг него вспыхивает сжимающееся кольцо, и только потом снаряды выходят из его позиции. Игрок всегда видит, кто и откуда стреляет.
- **У жабы свой облик, и стаи не однородны.** Окрас из восьми палитр и размер особи (`C.fauna.belzebufo.palettes`, `size`) выбираются детерминированно по месту обитания, поэтому жаба в одном зале всегда одна и та же, а в соседних — другая, крупнее или мельче. Глаза — не плоские точки, а выпуклые купола: они выпирают над головой, двигаются вместе с прыжком и дышат золотой радужкой, зрачком и бликом. Залпы бельзебуфо сейчас отключены (`encounter.belzebufo.canShoot: false`): жаба бьёт языком, прыгает и оставляет слизь, но не выпускает плотные волны снарядов. Одно значение `canShoot: true` возвращает их обратно.
- Жук не отстаёт: его `enemySpeed` почти не уступает аксолотлю, а рывок он сокращает подкопом (`encounter.beetle.dig`). Как только жук отстал, он уходит в камень и выныривает не где попало, а впереди игрока — на пути его движения (`digSpotAhead`), чтобы перекрыть дорогу, а не тащиться следом. Подкоп доступен с первой секунды (`digCooldown` стартует с нуля).
- Выстрелы жука вязкие (`encounter.beetle.stickyBullets`): они не гаснут о стены, а приклеиваются к ним и друг к другу, постепенно собираясь в опасные стенки из слипшейся массы. Прилипший снаряд остаётся до конца боя и продолжает ранить, поэтому такие стены приходится обходить. Общее число снарядов ограничено `stickyBulletCap` — самый старый прилипший уступает место новому.
- **Бой с жуком не подлагивает.** Преследователь идёт по прямой, пока видит игрока, а поиск пути включается только за препятствием и ограничен по глубине и числу узлов. Прилипшие снаряды ищут соседей через пространственный хэш, снаряды за пределами экрана не рисуются, а панель состояния обновляется раз в несколько кадров. При полусотне снарядов и слизи кадр укладывается в бюджет 60 FPS.
- Под жуком остаётся зелёная жижа (`encounter.beetle.slime`): капает с интервалом `interval`, держится до конца боя, наносит урон и замедляет аксолотля, пока он по ней идёт.
- Бельзебуфо не ползёт, а прыгает (`encounter.belzebufo.hop`): разбег, полёт по дуге и приземление. Точка прыжка берётся по кратчайшему пути (`hop.distance`), но только туда, куда ведёт прямая без стены, поэтому жаба не перелетает сквозь камень.
- Жаба нападает всегда, без броска шанса, но не с порога: вход в зал её не выдаёт. Она сидит в центре болота и поднимается на бой, когда аксолотль подходит к её плёсу на `C.faunaDynamics.roomTrigger` клеток (`encounter.belzebufo.perRoom`). До этого жаба почти сливается с водой и мхом: `roomReveal` управляет проявлением, а `roamReveal` и `roamStillHide` прячут засадных жаб, пока они неподвижны и игрок далеко. Раньше встреча могла не состояться по случайности — теперь она гарантирована.
- **Жабу можно встретить и в проходах, и в обычных комнатах, но всегда на болоте.** Болото — это не лужа вокруг жабы, а часть генерации мира: детерминированные по зерну и мировым координатам пятна swamp-тайлов (`C.world.swamp`) разбросаны по всему лабиринту крупными плёсами и остаются на месте, даже когда жаба ушла в бой или за край экрана. Засадная бельзебуфо не мигрирует по миру: она сидит на болоте с камышом и кувшинкой и патрулирует его прыжками на 1–2 клетки — присед, полёт по дуге, приземление — с долгими паузами между кочками (`roamHop`, `roamPatrolRadius`, `roamPatrolJump`, `roamPatrolPause`). Прыгать она может только на swamp-тайлы, поэтому ареал держится своего болота. Лапы в это время подбираются и разводятся вместе с прыжком, а не остаются неподвижными. На участке хватает одной жабы (`roamMaxFrogs`), и она нападает, когда аксолотль подходит вплотную (`C.faunaDynamics.roamChance`, `roamTrigger`).
- **Врагов стало заметно меньше, а встреча — событием.** Частота залов фауны (`C.world.faunaChance`) и доля бельзебуфо (`C.world.belzebufoShare`), как и частота засад (`roamChance`), снижены ещё сильнее: лабиринт между врагами ощущается пустым, а каждая схватка — редкой и оттого более интересной. Засадных жаб на участок не больше одной.
- **У каждого врага есть свой ареал, и он в него возвращается.** После любого исхода боя — и при гибели аксолотля, и после победы — засадная жаба не исчезает: она возвращается в своё болотце (`ZQ.restoreRoamFrog`) и снова сидит там. После победы пауза перед новой засадой длиннее (`roamVictoryCooldown`), чтобы игрок успел отойти.
- Язык бельзебуфо (`encounter.belzebufo.tongue`) достаёт аксолотля на `range` клеток по прямой и подтягивает его к жабе (`pullSpeed`), поэтому далеко от неё не убежать. Урона язык не наносит: он только хватает и тянет. Контактные i-frames его не гасят, а увернуться можно рывком (`dashTimer`).
- Жаба оставляет слизь и вокруг себя, и брызгами после каждого прыжка (`encounter.belzebufo.slime`): она держится до конца боя, наносит урон и замедляет аксолотля.
- **Болото — постоянный ландшафт, а не временная декорация.** Swamp-тайлы (`world.swamp`: ячейка, шанс, радиус) замешиваются в генерацию чанков рядом с обычными комнатами и проходами: это крупные плёсы в четверть экрана и больше, а зал бельзебуфо целиком залит водой. Цвет воды считается плавным мировым шумом, поэтому соседние клетки перетекают друг в друга, а не распадаются на шахматку; берег получает волнистую мшистую кромку, рябь и камыш рисуются крупными пятнами, а поверх пола отдельным проходом ложится туман. Болото остаётся на карте при уходе жабы, после боя и за пределами видимой области. На болоте спавнятся и патрулируют засадные жабы, так что ареал — это сам ландшафт, а не отдельный объект `frog.swamp`.
- Пока схватка или погоня не закончилась, новых врагов не ищут: вход в другую комнату не запускает вторую схватку поверх текущей.
- Интенсивность залпов идёт за волной трека: `ZQ.audio.peaks` задают громкость и атаки в текущем месте записи, а жанр (`C.battle.genres`) — общий уровень. Жанры: `calm` (спокойный), `rhythmic` (ритмичный) и `bullethell` (плотный буллет-хелл). Громкие доли сгущают снаряды, тихие проходы дают передышку.
- `Shift`, `Space`, `E` или кнопка `A` геймпада — рывок сквозь настоящие проходы; `F` или кнопка `X` геймпада — раскрыть зонт и отразить снаряд. Рывок — отдельная способность: пока Zemic её не открыл, он закрыт и в бою, и в погоне. Команды `рывок открыть` и `рывок закрыть` переключают гейт (порог задан в `C.battle.dash`), а `сдаться` выходит из схватки или погони без победы.
- Волны чередуются: края, веер, кольцо, спираль, дождь, перекрёстный огонь и самонаведение. Чем громче музыка и чем дольше держишься, тем активнее напор.
- Успех — дожить до конца трека; гибель и выход из воды работают по общим правилам, награда и сюжетный флаг выдаются только за успех.
- В комнате `umbrella` зонт выдаётся на время боя, а ритм-режим требует раскрывать его на долю трека; после успеха зонт остаётся у Zemic.
- Встречи должны быть редкими: схватка длится всю песню, поэтому `C.world.faunaChance` и `C.world.belzebufoShare` держат появление залов с бельзебуфо низким. Её встреча повторяемая, а появление управляется читом `шанс бельзебуфо`.
- Телепорт к врагу действительно начинает бой. При переносе Zemic текущая комната сбрасывается, поэтому вход в зал распознаётся заново и встреча запускается так же, как при обычном шаге, — раньше телепорт к противнику не поднимал схватку.

### Титанобоа

Титанобоа — не стрелок и не фоновая угроза, а сама змея, которая ползёт за Zemic по лабиринту. Погоня начинается при входе в её комнату и длится до конца трека (`durationMode: 'track'`): это долгий изматывающий забег, а не перестрелка.

- Змея не материализуется рядом с игроком: её голова изначально стоит в дальнем от входа углу собственного зала, и только потом кольца приходят в движение. Короткая пауза пробуждения (`C.chase.wakeTime`) даёт увидеть, что зал уже занят, — появление остаётся неожиданным, но не выглядит телепортом.
- Тело змеи состоит из десятков мировых клеток и повторяет путь головы; она проходит те же коридоры и сжимается в узких проходах, а не летит поверх стен. Стартовое тело длинное (`bodyLength: 70`): змея сразу заполняет зал, через который ползёт.
- Поиск пути не ограничен парой шагов: BFS идёт до `pathDepth` клеток и `pathNodes` узлов (`C.chase.pathDepth`, `pathNodes`), поэтому змея выбирает действительно короткий маршрут до аксолотля, а не идёт вдоль стены.
- Маршрут действительно кратчайший: шаг берётся из поля расстояний до аксолотля (`distanceField`), поэтому змея всегда идёт по ближайшей клетке к цели. Если аксолотль ушёл в сторону, змея сворачивает к нему по короткой оси (вбок), а не ползёт параллельно вверх или вниз.
- Чем дольше идёт погоня, тем длиннее становится змея: тело растёт вместе с давлением от стартовых `bodyLength` клеток до `maxBodyCells` (`bodyGrowth` задаёт прирост к концу трека).
- Одновременно тело расползается поперёк спины и постепенно заполняет комнату или проход собственной массой (`spreadHalfWidth`): в конце коридора уже не проскользнуть, остаётся только бежать.
- Ширина не застывает: тело дышит — то раздаётся, то сужается (`breatheSpeed`), поэтому змея выглядит живой. На повороте поперечные клетки схлопываются в доминирующую ось, а у самой кромки ширина сжимается обратно в позвоночник: масса никогда не вылезает за стену и в узком проходе собирается в тело.
- Движение рисуется плавно и векторно: отрисовка интерполирует позвоночник между прошлым и текущим шагом (`prevBody` → `body` по `stepTimer / interval`), поэтому змея ползёт, а не прыгает по тайлам. Масса для отрисовки считается по интерполированному позвоночнику, включая кадры роста тела.
- Голова идёт по проходимым клеткам, пытается отрезать путь и накрыть Zemic кольцами; **одно касание убивает** — второго шанса нет.
- Бег расходует выносливость, рывок помогает разорвать дистанцию; к концу погони змея ускоряется.
- Если аксолотль сильно оторвался, змея заметно ускоряется к его полю зрения (`C.chase.farDistance`, `farSpeedBoost`), а при огромном отрыве переносится в следующий прогруженный чанк и встречает героя на его пути (`teleportDistance`, `teleportArrive`, `teleportCooldown`).
- Темп музыки во время погони не меняется: скорость трека задаёт только сам игрок в плеере, автоматических сценических множителей нет.
- Победа — дослушать трек до конца: тогда титанобоа успокаивается, открывает проход и уходит в щель уже своего тела; сюжетная сцена выводится в общий лог.
- Убежать от снарядов здесь нельзя: снарядов нет, есть только ползущее тело, которое не устаёт.

### Живые диметродоны

Диметродоны — пассивные мобы Лабиринта, а не противники. Они не нападают: просто ползают по настоящим клеткам мира, греются и расползаются из своих залов.

- Каждый зал диметродонов (`faunaKind: 'dimetrodon'`) при первом приближении населяется небольшой группой (`C.faunaDynamics.roomStart`).
- **У каждого зала своя стая.** Стая зала выбирается детерминированно по его id (`seed:pack:<roomId>`) и задаёт окрас, форму и размер зверей: палитра из восьми вариантов (`C.faunaDynamics.packs`) — медная, изумрудная, лазурная, фиолетовая, пепельная, золотая, багровая и мятная, с разными узорами паруса (лучи, полосы, пятна, «глаза», штрихи, ромбы). Размер и настройки стаи (`size`, `sailScale`, `speedScale`) тоже различаются. В одном зале обычно живёт одна стая, а в соседних — другие, поэтому залы узнаются по обитателям.
- **Звери общаются внутри стаи.** Стая время от времени перекликается зовом (`callInterval`): один диметродон подаёт голос, и сородичи поблизости поворачиваются к нему. Двое близких сородичей могут перейти к брачной демонстрации (`tryCourtship`): они синхронно поднимают и разворачивают парус, показывая узор. Это язык стаи, а не реакция на аксолотля.
- В зале диметродонов есть вода и зелень: детерминированные водоёмы и кусты травы (`waterPools`, `plantPatches` в `C.faunaDynamics`) считаются по зерну мира и сохраняются вместе с игрой. Без них звери просто не могли бы тут обитать. Вода и растения не пересекаются: зелень не растёт в воде.
- **Вода сплошная, а не набор клеток.** Плёс генерируется цельным блобом (`waterBlob`) и хранится как готовые круги (`feature.pools`) плюс список водных клеток для логики плавания. Поэтому лужа рисуется одним тёмным пятном с рябью, а не россыпью отдельных кружков.
- **Лужи большие, и в них можно плавать.** Водоёмы выросли (`waterPools`): диметродон — полуводный зверь, он заходит в воду, и там его движения замедляются и расходятся кругами по поверхности. Симуляция отмечает плавание (`swimming`).
- **Анимация зверя стала живее.** Хвост виляет в такт шагу, лапы переступают полноценным циклом (бедро, ступня, подъём в фазе переноса), корпус покачивается при ходьбе, а голова чуть кивает и время от времени мигает.
- Голод и жажда: время от времени диметродон идёт к ближайшему водоёму или растению, пьёт или щиплет траву и коротко отдыхает (`needMin`, `needMax`). Трапеза анимирована: голова опускается к земле, а из пасти разлетаются зелёные травинки (еда) или капли воды (питьё).
- **Парус особенно ярок.** Спинной парус — и терморегулятор, и средство привлечения партнёра, поэтому он выделяется ярче тела: у каждого окраса свой рисунок, а во время зова и демонстрации он подсвечивается и разворачивается.
- Диметродонов можно подталкивать: когда аксолотль упирается в моба, тот мягко уходит в сторону движения (`ZQ.faunaPush`), а не превращается в стену. Если за мобом стена или другой зверь, толчок не проходит.
- Они ходят только по проходимым клеткам, иногда останавливаются передохнуть и постепенно разбредаются по коридорам.
- У них есть коллизия: аксолотль не проходит сквозь диметродона, а сами мобы не встают на одну клетку. Хитбокс коллизии заметно больше самого зверя (`collisionRadius`), поэтому звери не сливаются в одну точку и не пропускают героя сквозь себя. Если моб уже накрыл героя, тот может выйти — застрять нельзя.
- Пока игрок в их зале, звучит альбом «Кузя»: cue `dimetrodon` выбирает дорожку детерминированно по id комнаты (`C.musicCues.dimetrodon.track`), поэтому каждая стая слышит свою песню, а темп трека никогда не меняется автоматически.
- Популяция растёт: раз в `growthInterval` секунд появляется новый диметродон, пока не достигнут предел `cap`.
- Симуляция идёт в радиусе `simulateRadius` вокруг аксолотля; далёкие мобы замирают, поэтому мир не тормозит.
- Состояние (позиции, посев залов, вода и зелень, счётчик рождений) сохраняется вместе с игрой и переживает загрузку.

### Зеркальный зал и Вишня

Зеркальный зал — фиксированная сюжетная комната к северо-востоку от Скрижали (`fixedRooms.mirror`, клетка `3,2`). Это не бой и не ловушка: здесь живёт **Вишня** — девчонка-отражение, собранная из мотивов стихотворения про зеркало, телефон, вишнёвые сигареты и вопрос «кто здесь лишняя». Она не враг по умолчанию и не выдаёт награду за простой разговор.

- В зале стоят три высокие рамы: **зеркало с телефоном**, **зеркало с двумя** и **зеркало с собакой**. У каждой рамы своя сцена и своя подсказка. Осмотреть все три можно клавишей `E` рядом с рамой или командой `посмотреть`.
- Разговор с Вишней начинается с `E` или `посмотреть`. Она просит осмотреть все три зеркала: каждое показывает, у кого нет собственного отражения. После третьего осмотра она задаёт вопрос: «Кто здесь лишняя?»
- Ответ решает исход. `ответить я` — доверие: Вишня не стирает Zemic, отдаёт **осколок зеркала** и выпускает из-за рамы собаку **Косточку**. `ответить ты` — вражда: зеркала поворачиваются, Вишня бросается в погоню по залу, и касание убивает (`ZQ.die('отражение')`). `ответить никто` — нейтральный исход: она уходит, оставляя пустые рамы.
- Враждебное отражение можно остановить словом `прости` или просто выйти из зала. Тогда Вишня отступает в глубину рамы и больше не преследует.
- **Осколок зеркала** — пассивный предмет: пока он в инвентаре, засадные бельзебуфо выдают себя красным бликом на болоте. Если в инвентаре нет места, осколок ждёт в раме и выдаётся позже, когда освободится ячейка.
- **Косточка** идёт за Zemic по миру, держится позади и предупреждает о близких засадах и залах с бельзебуфо. Собака не участвует в бою и не блокирует проход.
- Состояние Вишни (`mirrorPhase`), осмотренные рамы и ответ входят в сохранение. Один и тот же зал нельзя «переиграть» без новой игры: доверие, вражда и уход остаются в силе.
- Сюжетная ветвь «Зеркальный зал» появляется в графе `сюжет` как optional-узел и считается пройденной после любого ответа (`mirrorAnswer`).
- Концепция персонажа, карта мотивов и таблица исходов: `concept/vishnya_mirror_hall.md`.

### Читы

Для проверки дальних комнат без долгого блуждания есть чит-телепорт. Он ищет ближайшую подходящую комнату, при необходимости досоздаёт чанки кольцами вокруг игрока (до девяти колец) и переносит Zemic на свободную клетку.

- `телепорт титанобоа`, `телепорт зонт`, `телепорт скрижаль`, `телепорт бельзебуфо`, `телепорт перекрёсток` — по роли, фауне или части имени комнаты.
- `телепорт чанк 2 -1` — в ближайшую комнату указанного чанка.
- `телепорт` без аргумента показывает справку и список целей.
- Во время схватки или погони телепорт отказывает, чтобы не ломать бой.
- `шансы`, `шанс фауны 0.4`, `шанс сюжет 0.25`, `шанс бельзебуфо 0.5` меняют шансы генерации для ещё не созданных комнат и сразу пересобирают мир.

## Что работает в прототипе

- Полноэкранная компоновка без обрезки: 16:9 и 9:16 поддерживаются, в кадре остаётся не меньше 14.5×13.2 клеток; портрет по умолчанию отдаёт игре 60% высоты.
- Восьминаправленный спрайт Zemic: восемь групп по четыре кадра шага — вниз, вверх, влево, вправо и четыре диагонали.
- Скрижаль — центр мира и точка появления после гибели, но не «база» и не безопасная зона.
- Бесконечный ленивый Лабиринт по чанкам с детерминированным seed. Новый мир создаётся командой `новая игра`.
- «Слепой зал» остался атмосферной комнатой без теней и урона: он проверяет память о направлении, а не реакцию.
- Пыль и мелкие частицы живут в координатах мира и не приклеены к экрану; при ходьбе они не перегенерируются, а остаются на месте.
- Инвентарь с предметами, картой, мелком и картой «Очарование». Предметы можно выносить на стол. Рюкзак — отдельная вещь и отдельная команда-отчёт; инвентарь открывается командой `инвентарь`.
- Гибель возвращает Zemic к Скрижали, а рюкзак со всем содержимым остаётся в месте гибели. Повторная гибель не удаляет прежние рюкзаки: каждый остаётся отдельным объектом, пока его не подберут.
- Терминал с очередью сообщений, настраиваемой скоростью печати, единой типографикой, переопределениями для терминала и стола, записью действий и историей команд. Команда `история` показывает буфер введённых команд. Сюжет, гибель и результат испытания выводятся в общий лог.
- Первое системное сообщение объединяет версию ядра и сборки, время загрузки мира, число комнат и чанков, seed и справку по управлению.
- Стол поддерживает свободное размещение, перетаскивание, удаление, бесконечную сетку, элементы из предметов, команды и отдельные клавиши. Одна клавиша может запускать несколько целей; связи рисуются линиями со стрелками. Состояние стола и привязки сохраняются. Схемы управления включают клавиатуру, геймпад, телефон и мышь; закрытие стола — крестиком `×`. Инвентарь использует ту же канву (`js/canvas.js`, `css/canvas.css`): одинаковые жесты, сетка, масштаб, панорамирование и перетаскивание без внутренних ограничений.
- Интерактивная схема клавиатуры на столе добавляет клавишу на стол одним нажатием; живые клавиши сразу запускают свои цели. Отдельного ядра управления с подсветкой клавиш и строки движения с кнопками-стрелками больше нет.
- Сохранение, загрузка, импорт и экспорт мира доступны командами и кнопками в `настройки` → «Данные»; в интерфейс терминала они не вынесены. Именованные слоты хранятся отдельно от автосохранения, их можно выбирать, переименовывать и удалять.
- Переключение языка командой `язык` (русский/английский/немецкий) меняет интерфейс, терминал и доступные псевдонимы команд.
- Схватки идут прямо в Лабиринте: Zemic-аксолотль двигается по настоящим клеткам, снаряды и зонт живут в мировых координатах, а не на отдельной арене. Вход в `beetle`, `umbrella` или `belzebufo` сразу запускает воду без согласия игрока; нужно продержаться до конца трека рывком и зонтом. Бельзебуфо не ползёт, а прыгает, бьёт длинным языком и оставляет слизь; он нападает всегда и поджидает не только в зале, но и в проходах лабиринта.
- Титанобоа — долгая погоня от ползущего тела: длинная змея из десятков клеток идёт по кратчайшему маршруту вдоль большей оси разрыва, дышит шириной, сжимается в узких местах и никогда не вылезает за стену, растёт и толстеет, а рисуется плавно и векторно. Одно касание убивает, а победа приходит только в конце трека.
- Живые диметродоны ползают по Лабиринту, расползаются из своих залов, ходят к воде и зелени (которые не пересекаются), едят и пьют с частицами, размножаются и поддаются толчку; это пассивные мобы, а не враги. У каждого зала своя стая со своим окрасом, формой и размером, звери перекликаются зовом и синхронно показывают яркий узорный парус, плавают в больших лужах, а увеличенный хитбокс не даёт им сливаться.
- Зеркальный зал: три осматриваемые рамы, разговор с Вишней и три исхода — доверие с осколком зеркала и собакой Косточкой, враждебная погоня с гибелью от касания и нейтральный уход. `прости` останавливает вражду, осколок подсвечивает засадных жаб, а собака предупреждает о них. Состояние зала сохраняется.
- Чит-телепорт `телепорт титанобоа` / `телепорт зонт` / `телепорт зеркало` / `телепорт чанк 2 -1` ищет ближайшую нужную комнату в кольцах чанков и переносит к ней; во время боя и погони отказывает.
- Испытание «Круг Очарования»: 35 секунд, три искры, три временные печати, нужно закрыть не меньше двух. Искры — health-подобный ресурс только внутри испытания; при их исчерпании Zemic погибает по общим правилам. Если время истекло без нужного числа печатей, испытание можно повторить без гибели и без потери предметов.
- После успешного испытания в центре комнаты появляется карта «Очарование». Её можно взять, положить на стол и вызвать командой `очаровать`.
- Музыкальные cue-треки: лес для обычного Лабиринта, `gall` для титанобоа и Слепого зала, `trachea` для выживания с бельзебуфо, отдельный трек для зонта, `lungs` для схватки с жуком и альбом «Кузя» для зала диметродонов (дорожка выбирается по комнате). Команда `плеер` (синоним `музыка`) и кнопка в настройках открывают проигрыватель; в нём есть пауза, стоп с возвратом в начало, перемотка, громкость, волна, скорость 0.5×–2× и выбор любого альбома и трека. Показанная длительность учитывает фактическую скорость воспроизведения. Темп трека меняет только сам игрок в плеере — автоматических сценических множителей нет.
- Сохранение прогресса в `localStorage`: seed, позиция, флаги, посещённые комнаты, предметы, рюкзаки, метки, позиции узлов инвентаря, элементы стола, связи клавиш и просмотренные сюжетные сцены. Состояние испытания намеренно не сохраняется между перезагрузками.

## Сборка и версия

Игра остаётся статической и не требует сборщика. Небольшой скрипт `build.js` увеличивает номер сборки и записывает его в `js/build-info.js`:

```bash
node build.js
```

После запуска номер сборки в `js/build-info.js` увеличивается на единицу, а версия берётся из `js/config.js` (`version`). В игре первое системное сообщение показывает `Версия ядра: <версия> · сборка <номер>`, так что версию можно проверить прямо в терминале. Запускать `build.js` нужно после изменений, которые должны попасть в новую сборку.

## Музыка и кассеты

Каталог собирается из `/home/zqwy/smb/apps/tiddlywiki/tiddlywiki-data/files/src/tracks/`: каждая папка альбома становится кассетой, а её основные дорожки — треками этой кассеты. Сканер `tools/sync-tracks.js` не копирует музыку к игре: он только перезаписывает `js/tracks.generated.js`, где у каждой дорожки стоит относительная ссылка `../../src/tracks/<album>/<track>.opus`. Сами файлы живут в общем архиве и не дублируются в `assets/music`.

```bash
node tools/sync-tracks.js
node tools/sync-tracks.js --source /path/to/src/tracks
```

`js/config.js` при загрузке объединяет сгенерированный каталог с вручную заданными треками (`forest`, `umbrella`, `gall`, `lungs`, `trachea`, `poljana`), создаёт кассеты и автоматически добавляет все известные дорожки в `state.cassettes`. Поэтому новый альбом или трек появляется в плеере после повторного запуска сканера без ручной правки сохранения. Cue-таблица по-прежнему переключает трек при входе в комнату или начале схватки; для сцен с целым альбомом (`dimetrodon`) дорожка выбирается детерминированно по seed'у комнаты.

Команда `плеер` (синоним `музыка`) открывает проигрыватель, также доступный из `настройки` → «Музыка». В нём есть символические кнопки паузы `▶` / `❚❚` и стопа `■` (стоп останавливает и перематывает в начало), перемотка, громкость с отдельной кнопкой выключения, волновая дорожка, скорость 0.5×–2× и библиотека: список кассет-альбомов и дорожек выбранной кассеты. Показанная длительность пересчитывается по фактической скорости воспроизведения, поэтому при 2× трек заканчивается вдвое быстрее и таймер показывает именно это.

Волновая дорожка показывает весь трек, а не только последние доли секунды: файл один раз скачивается и декодируется целиком, после чего из него считаются нормализованные пики. Поэтому по волне видно всю звуковую дорожку, а нажатие или перетаскивание по ней перематывает в любую точку. Громкость и включение хранятся в настройках терминала. Браузер может ждать первого жеста пользователя — после клика или нажатия клавиши воспроизведение начинается автоматически.

## Аркадный автомат

В процедурных залах Лабиринта иногда стоит аркадный автомат. Шанс задаётся `C.world.arcadeChance` (по умолчанию `0.16`), а место детерминировано seed'ом и комнатой: сохранённый мир показывает автомат там же, где вы его нашли. Автоматов может быть несколько — каждый процедурный зал бросает свой шанс независимо. Подойдите к корпусу и нажмите `E`, введите `аркада` / `автомат` или используйте `телепорт автомат`, чтобы проверить ближайший.

Автомат не заводит отдельную экономику кассет. Он показывает только кассеты из `state.cassettes` и только те дорожки, для которых в `../rhythm_catalog/data/catalog.json` есть чарт. Сопоставление идёт по исходному пути: `track.source` из `js/tracks.generated.js` сравнивается с `track.path` ритм-каталога без `../../src/tracks/`. Поэтому альбомы без чартов (`dark_happy`, `labyrinth`, `lost`) в автомате не появляются, а JSON-файлы не дублируются.

Выбор дорожки запускает самостоятельную игру `../rhythm_catalog/index.html?embed=zqwy` в iframe прямо во вкладке терминала. Ритм-каталог остаётся отдельной игрой: без параметра `embed` он открывает собственные меню и работает как раньше. В режиме автомата он ждёт команды `start` / `pause` / `resume` / `stop` / `lang` от родительской страницы и отвечает сообщениями `ready` / `track` / `result` / `error` / `exit`. Хост присылает выбранную дорожку, показывает текущий трек и извлекает кассету кнопкой `⏏`.

Прогресс аркады — это только записи и терминальный лог: `state.arcade = { cassette, album, track, plays, last }`. Личные рекорды по-прежнему хранит сам ритм-каталог в `localStorage` (`rhythmCatalog.bests.v1`), а автомат читает их и показывает рядом с дорожкой. Никаких предметов, валюты или наград за игру нет. Пока вкладка открыта, мир на паузе, а фоновый трек Лабиринта останавливается и возвращается после закрытия.

- титанобоа стартует с длинным телом из 70 мировых клеток, голова идёт по проходимым клеткам, тело сжимается в узких проходах, по ходу погони змея удлиняется и расползается поперёк прохода, а движение рисуется плавно и векторно (интерполяция позвоночника между шагами); шаг идёт по кратчайшему маршруту вдоль большей оси разрыва, ширина дышит и не выходит за стены (масса всегда на проходимых клетках); погоня длится до конца трека и заканчивается спокойствием и сюжетной сценой; при большом отрыве змея ускоряется и переносится вперёд по ходу игрока, а касание убивает мгновенно;
- живые диметродоны населяют свои залы с цельными лужами и зеленью, которые не пересекаются, идут к ним по голоду и жажде и трапезничают с частицами (травинки или капли), ползают по проходимым клеткам, не пропускают аксолотля сквозь себя, но поддаются толчку, разбредаются и размножаются до предела, а их состояние переживает сохранение; их анимация живая (хвост виляет, лапы переступают, голова кивает и мигает), вода рисуется сплошным блобом с плаванием, а в их зале звучит альбом «Кузя» с дорожкой, выбранной по комнате;
- залпы выходят из позиции преследователя после телеграфа, жук почти не отстаёт и роет подкоп вперёд по ходу игрока, а его вязкие выстрелы прилипают к стенам и друг к другу, оставляя под собой замедляющую жижу; бельзебуфо прыгает по дуге только туда, куда ведёт прямая без стены, оставляет слизь вокруг себя и брызгами после прыжка, а длинным языком по прямой подтягивает аксолотля к себе без урона; залпы жабы временно выключены (`canShoot: false`), поэтому бой держится на прыжках, языке и слизи;
- бельзебуфо получает свой окрас из восьми палитр и свой размер, детерминированные по месту обитания (стаи не однородны); болото — постоянные swamp-тайлы в генерации мира, крупные плёсы по всему лабиринту и почти полный воды зал бельзебуфо; засадная жаба появляется и патрулирует только на болотных тайлах, прыгая на 1–2 клетки с анимированными лапами, и после любого боя — в том числе после победы — возвращается на ареал (`ZQ.restoreRoamFrog`); одновременно на участке не больше одной засадной жабы, а частота залов и засад снижена ещё сильнее;
- чит `телепорт титанобоа` находит ближайшую комнату `r4_0` в чанке `0,0`, не запускает бой и сообщает чанк и дистанцию; неизвестная цель получает отказ;
- старая привязка `element.key` мигрирует в отдельный элемент-клавишу, собирает обе цели и удаляет поле `key` у целей;
- испытание открывает игровую сцену, провал и успех сразу возвращают в `main` и выводятся в лог; экрана результата и кнопки «Дальше» нет;
- аркадный автомат стоит на полу процедурного зала, подсказка «рядом: сыграть на автомате · E» появляется в радиусе 1.35 тайла, описание комнаты сообщает об автомате, а `телепорт автомат` ведёт к ближайшему корпусу;
- вкладка `arcade` показывает только кассеты из `state.cassettes` с чартами: 28 кассет и 257 дорожек, альбомы без чартов (`dark_happy`, `labyrinth`, `lost`) не появляются;
- выбранная дорожка стартует в iframe `../rhythm_catalog/index.html?embed=zqwy`, кадр забирает фокус (D F J K и стрелки работают сразу), Esc внутри кадра ставит паузу, `⏏` возвращает к списку, а результат и рекорд пишутся в лог и `state.arcade`;
- после закрытия автомата вкладка возвращается в `main`, пауза снимается, а фоновый трек Лабиринта продолжается только если играл до открытия;
- в ходе прогона не возникло JS-ошибок.

Что не проверено:

- Полное 35-секундное прохождение испытания вручную с реальным уклонением. Ветки успеха и провала проверялись принудительным завершением через debug API.
- Полный трек погони от титанобоа вручную без принудительного завершения; проверялись старт, длинное тело, следование по клеткам, контакт, HUD, ускорение/телепорт при отрыве и ветка спокойствия.
- Полный бой с бельзебуфо вручную до конца трека: прыжки, язык и слизь проверялись программно (состояния прыжка, притягивание языком без урона, число капель), а не глазами. Отсутствие урона от языка, спасение рывком и болотный тайл под засадной жабой проверены отдельным CDP-смоуком.
- Трапеза диметродонов наблюдалась программно (состояние `eat`/`drink` и частицы), а не покадрово вживую.
- Реальные iOS/Safari, Android и физические сенсорные устройства; щипок, перетаскивание разделителя пальцем и панорамирование проверены синтетическими pointer-событиями.
- Подключение физического геймпада: схема и опрос Gamepad API реализованы, но проверялись без реального устройства.
- Слышимость трека и подбор громкости на реальных колонках/наушниках.
- Публикация на живом GitHub Pages.

## Сохранение и отладка

Ключ сохранения: `zqwy.labyrinth.prototype.v1`. Версия сохранения: `1`. Seed нового мира создаётся случайно при первом запуске и при команде `новая игра`; сохранённый seed восстанавливается при следующем открытии. Пропорция разделителя хранится отдельно в `zqwy.labyrinth.split.v1`, настройки терминала — в `zqwy.labyrinth.terminal.v1`. Элементы стола, клавиши и их связи входят в основное сохранение.

Сохранение, загрузка, импорт и экспорт доступны командами `сохранить`, `загрузить`, `импорт`, `экспорт` и кнопками в `настройки` → «Данные». Экспорт скачивает JSON-файл `zqwy-world-<seed>.json` с состоянием мира, seed, координатами чанков и метаданными; импорт принимает такой же файл или JSON именованного слота и восстанавливает мир без перезагрузки страницы.

Именованные сохранения лежат отдельно от автосохранения в ключе `zqwy.labyrinth.slots.v1`. В настройках можно выбрать слот из списка, сохранить текущий мир под именем, загрузить, переименовать или удалить его. Имя ограничено 40 символами, слоты сортируются по времени сохранения. Те же действия доступны командами `слоты`, `сохранить слот <имя>`, `загрузить слот <имя>`, `переименовать слот <старое> → <новое>` и `удалить слот <имя>`.

При `?debug=1` в URL устанавливается `window.__zqwy` — только для разработки и проверок. Он умеет возвращать снимок состояния, телепортировать игрока, переходить в комнату по роли, выдавать предмет, вызывать гибель, запускать и завершать испытание, закрывать представления, создавать новый мир, управлять логгированием, читать сюжетное дерево, добавлять элементы и клавиши, связывать и развязывать цели, двигать и масштабировать стол, сохранять состояние. В обычном запуске API отсутствует.

## Заглушки и следующий этап

- «Очарование» остаётся нейтральной заглушкой: команда `очаровать` отвечает, что способность ещё не подключена; эффекта, ограничения или баланса нет.
- Испытание имеет базовую настройку (35 секунд, 3 искры, 3 печати, порог 2) и требует отдельного балансировочного прохода.
- Мир генерируется бесконечно, но сюжетных комнат и уникальных событий пока конечный набор; фоновые комнаты различаются структурой и именами.
- Нет внешних библиотек, сборщика и серверной части; всё работает на нативных HTML/CSS/JS.

- Сюжетные комнаты «Скрижаль», «Слепой зал», «Низкий свод», «Круг Очарования», «Кладовая», «Тихий перекрёсток» и их тексты.

- Конкретная структура домашнего чанка 5×5, расположение комнат и испытания.

## Важные открытые решения

1. **Останавливать ли игровое время при открытом столе.** Сейчас время останавливается, как и при открытом рюкзаке/карте. В доступном Godot-проекте это не подтверждено.
2. **Эффект и стоимость «Очарования».** Механика предмета, размещения, вызова и ответа терминала готова; сам эффект, ограничения и баланс должны проектироваться отдельным модулем.
3. **Нужны ли разные треки для комнат.** Сейчас один зацикленный файл на весь Лабиринт; cue-таблица готова к разделению, но новые файлы не добавлялись.
