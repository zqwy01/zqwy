# Portfolio and CV: What to show and what to fix

date: 2026-11-24

## Three case studies worth putting on public GitHub

### 1. Search for the personal portal

- What to show: a unified index of 445 records (11 pages, 39 links, 10 games, 40 releases, 296 tracks, 49 notes), 51 synonym groups, RU/EN dictionaries, transliteration, phrase aliases, typo-tolerant search via `editDistanceWithin`, highlighting via `document.createTreeWalker`, `Ctrl/Cmd+F`.
- Files: `dev/scripts/menu.js`, `scripts/build_search_index.mjs`, `dev/data/search-index.json`, `dev/data/search-synonyms.json`.
- Case format: problem → index architecture → difficulties with RU/EN and typos → result → what could be improved.

### 2. Universal audio player

- What to show: 9 engines (`html5`, `wavesurfer`, `peaks`, `howler`, `waviz`, `mediaelement`, `amplitude`, `aplayer`, `jplayer`) on a single `<audio>`; a shared `AudioContext`; EQ ±36 dB; limiter as the final output stage; 0 dBFS peak meter; draggable parametric EQ; crossfade via `GainNode`; RMS analysis of the start of a track; Media Session API; queue and `localStorage`.
- Files: `dev/scripts/player.js`, `dev/vendor/`, `dev/scripts/music.js`.
- Case format: why 9 engines, how identical behaviour is ensured, why local copies instead of CDN, how the peak is measured, what the interface looks like.

### 3. Build pipeline and deployment

- What to show: `dev/` + `src/` → generators → `dist/` → Docker `serve`; minification with terser/clean-css/html-minifier; `cp -al` hard links with fallback to `cp -a`; SMB-safe writes; excluding games from minification; auto-incrementing build number.
- Files: `scripts/build_dist.sh`, `scripts/build_music_catalog.mjs`, `scripts/build_covers.py`, `scripts/build_version.mjs`, `Dockerfile`.
- Case format: input data, artefacts, why this order of steps, SMB problems and how they were solved.

## What must be fixed before applying

1. **Public repository.** The site is already published via GitHub Pages, but `dev/links/index.html` has no link to GitHub. Add a link to the repository and to the three case studies.
2. **Don't commit 552 MB of audio.** Make a demo branch with a few tracks, covers and startup instructions; keep the full `src/tracks/` out of git.
3. **Update the README.** The record count is outdated (413 versus the actual 445), as is the Docker description: the `Dockerfile` is actually two-stage and builds `dist` inside the image, while the host `dist` mount in `docker-compose.yaml` is commented out.
4. **Close the gap with job-posting stacks.** If the goal is frontend: one small TypeScript + React case study. If the goal is DevOps: a lab setup with Terraform/Kubernetes and a cloud. Don't rewrite the main project — add a compact proof-of-work project.
5. **Tests.** CDP tests already exist, but the README records a baseline of `23 PASS / 14 FAIL`. Either fix them or state explicitly: "known baseline, new checks pass".

## CV structure

1. Headline: per `01. Позиционирование и роли.md`.
2. Summary: 3–4 lines about the T-shaped profile and the three case studies.
3. Skills: split into `Frontend`, `Audio/Web`, `Infrastructure`, `Tooling`.
4. Experience: to be supplied by the author — companies, roles, dates, measurable results.
5. Projects: the three cases above, 3–5 lines each.
6. Education: to be supplied by the author.
7. Languages: RU native, EN — state the level honestly.

## What the author needs to provide so the CV isn't "generic"

- Commercial experience: where, in what role, when, what was done, how the result was measured.
- Education: institution, specialisation, years.
- English level: reading / writing / speaking, whether there is experience corresponding with foreigners.
- Current salary and desired range in RUB/USD — the priority of stable income makes this critical.
- City and time zone; willingness to relocate outside the EU and outside the Georgia/Armenia/Turkey/UAE/Kazakhstan/Serbia list.
- Constraints: health, family, animals, equipment, relocation budget.
