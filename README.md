Правило простое: правки вносятся в `dev/`, на сайт попадает `dist/`.
Правка в `dist/` пропадёт при следующей сборке.

`dev/vendor/` и `dev/scripts/` намеренно разделены: в `scripts/` лежит наш
код, который можно править и минифицировать, а в `vendor/` — закреплённые
копии сторонних библиотек для движков плеера. Они загружаются лениво только
при выборе соответствующего движка и никогда не заменяются CDN: SMB-раздел
не любит symlink, а локальные копии гарантируют офлайн-работу. Аналогично
`dev/assets/icons/` — это first-party рантайм-иконки сайта (favicon и логотипы
ссылок), а `src/icons/` остаётся каталогом исходной/утилитарной графики;
новые логотипы ссылок туда не кладутся.

## Сборка

```bash
cd /home/zqwy/smb/sda/apps/zqwy
npm install --no-bin-links   # SMB-раздел не поддерживает symlink
npm run build                # или: bash scripts/build_dist.sh
```

При сборке Docker-образа (`docker compose up --build` / `docker build`) в этап `build` копируются `dev/`, `scripts/` и весь `src/`, поэтому генерация каталога музыки (из `src/tracks/`), заметок (`wiki/zqwy` из `src/notes/`) и обновление индекса поиска выполняются автоматически на каждом Docker-сборке. По умолчанию `docker-compose.yaml` отдаёт именно этот собранный в образе `dist`, поэтому после пересборки контейнер получает актуальные треки и заметки.

Если включить bind-mount `./dist:/app/dist:ro`, контейнер будет отдавать хостовую сборку и тогда актуальность каталога/заметок зависит от локального `npm run build` на хосте.

`npm run build` очищает `dist/`, копирует туда `dev/` и минифицирует
HTML/CSS/JS (`terser`, `clean-css-cli`, `html-minifier-terser`).
Скрипт берёт точки входа пакетов из `node_modules/` напрямую, поэтому
работает и без `.bin`-ссылок.

Версия в меню (`settings` → «Версия сборки») берётся из
`dev/data/build-info.json`. При каждой сборке `scripts/build_version.mjs`
увеличивает число в `scripts/.build-number` на единицу и записывает его в
поле `build`: в меню показывается `v1.0.0 · сборка 42 · <хеш>` (English:
`build 42`). Human-readable версия задаётся в `package.json`, хеш — из git
(в Docker отсутствует). Для CI/Docker номер можно передать переменной
`BUILD_NUMBER=42` — тогда файл-счётчик не меняется.

Перед копированием сборка пересоздаёт обложки в `src/covers/`
(`python3 scripts/build_covers.py`, отдельно — `npm run covers`), затем
`dev/data/music-catalog.json` из `src/tracks/`
(`node scripts/build_music_catalog.mjs`, отдельно — `npm run catalog`),
затем страницы `dev/wiki/zqwy/` из `src/notes/`
(`node scripts/build_wiki_notes.mjs`, отдельно — `npm run notes`) и только
после этого `dev/data/search-index.json` из страниц сайта, каталога музыки,
заметок и `search-synonyms.json` (`node scripts/build_search_index.mjs`,
отдельно — `npm run index`). Генератор заметок пишет полный текст заметки и
превращает мягкие переносы markdown в явные `<br>`, чтобы минификация HTML не
склеивала строки. Индекс поиска публикует фразовые алиасы в поле `phrases`, не
смешивая их с `synonyms`, поэтому число групп синонимов остаётся прежним.
Все генерируемые файлы — производные, вручную их править не нужно (исключение
— список синонимов и сами markdown-заметки).

В `dist/` публикуется и каталог `src/` (аудио, обложки): на SMB работают
жёсткие ссылки, поэтому `cp -al` не дублирует 546 МБ треков на диске.
Если жёсткие ссылки недоступны, сборка откатывается к обычному `cp -a`.
Пути в плеере имеют вид `../../src/...`, поэтому они работают и когда
корнем сайта служит `dist/`, и когда проект открывается целиком
(страница music тогда живёт по адресу `/dist/music/`).

## Устройство

Используется тот же переключатель меню, что и в
`/home/zqwy/smb/sda/apps/tiddlywiki/tiddlywiki-data/files/dev/pages/biela.html`
(шаблон `dev/templates/menu.html`):

- **Один постоянный блок**: кнопка-логотип (`#menuOpenButton`) и поле
  поиска (`#siteSearch` / `#siteSearchInput`) стоят в одной строке.
- Поиск всегда находится справа от логотипа. Открытие меню только
  показывает каталог: логотип и поиск не двигаются, не скрываются и
  остаются выше оверлея (`z-index: 1000000`).
- Поле поиска **компактное в покое** (по ширине плейсхолдера) и плавно
  растёт по мере ввода, пока не упрётся в ширину колонки. Группа
  логотип + поиск при этом остаётся центрированной: логотип сдвигается
  влево ровно настолько, насколько выросло поле.
- Меню (`#siteMenu`) — модальный оверлей с каталогом и настройками.
  Внутри меню отдельного поля поиска нет.
- Стили/поведение взяты и адаптированы из `tiddlywiki-data`:
  - `files/dev/styles/containers/menu/menu.css`
  - `files/dev/styles/containers/menu/menu_logo.css`
  - `files/dev/scripts/containers/menu/menu.js`

## Разделы внутри меню

- **Каталог**
  - `#wiki` — хранение текстовой информации, формат **markdown**
    (преобразование в HTML движком):
    - `#tiddlywiki` → `./wiki/tiddlywiki/`
    - `#obsidian` → `./wiki/obsidian/`
    - `#logseq` → `./wiki/logseq/`
    - `#quartz5` → `./wiki/quartz/`
    - `#zqwy` → `./wiki/zqwy/` — заметки в markdown из `src/notes/`
  - `#game` → `./game/`
  - `#music` → `./music/`
  - `#photo` → `./photo/`
  - `#links` → `./links/`
  - `#settings` — глобальные настройки сайта (тема, язык интерфейса
    RU/EN, запоминание запроса, версия сборки), сохраняются в `localStorage`.
    Выбор темы и языка сразу показывается на сайте **до** нажатия «Сохранить»:
    чёрный фон плавно переходит в белый (и наоборот), а текст меняет цвет
    вместе с фоном — мягкое свечение вокруг букв сохраняет контраст в момент
    перехода. Язык интерфейса меняется с плавным затуханием/проявлением текста;
    подписи кнопок каталога тоже переводятся. Кнопка раскрывается так же,
    как пункты каталога (анимация).
- Пункты с подразделами (`wiki`, `settings`) раскрываются плавно,
  шеврон поворачивается.
- При открытии меню пункты каталога появляются **по очереди, от первого
  к последнему** (задержка задаётся через `--i`).
- Вместо решётки `#` у каждого пункта каталога стоит понятная иконка
  (inline SVG: книга для wiki, ромб для obsidian, геймпад для game, нота
  для music, камера для photo, стрелка наружу для links, шестерня для settings
  и т.д.). Иконки наследуют цвет текста и работают в обеих темах.

## Оформление

- Чистый чёрно-белый режим: тёмная тема — чёрный фон/белый текст,
  светлая — белый фон/чёрный текст (без градиентов). Переключение темы
  анимируется: фон, текст, границы, иконки и тени переходят одновременно,
  а мягкий нейтральный ореол вокруг текста сохраняет читаемость в момент
  инверсии. `prefers-reduced-motion` сводит анимацию к одному кадру.
- Заголовок `zqwy` и подзаголовок — под блоком логотип + поиск.
- В светлой теме цвет логотипа **инвертируется** (`filter: invert(1)`),
  в тёмной остаётся исходным.
- Логотип-кнопка и поле поиска видны и корректно окрашены в обеих темах.
- Логотип и поиск находятся выше оверлея меню, поэтому не исчезают при его
  открытии. Строка `.menu-button-container` расположена в начале страницы и
  прокручивается вместе с содержимым; `html/body` используют `overflow-x: clip`,
  чтобы избежать горизонтальной прокрутки.
- `dev/assets/icons/favicon.ico` подключён как favicon сайта
  (`rel="icon"`).
- Содержимое меню выровнено по той же ширине, что и блок логотип + поиск.
- Пустой заголовок меню не занимает места, текст «Меню» в оверлее
  отсутствует.
- Нативные контролы (radio/checkbox, скроллбары) следуют выбранной теме
  через `color-scheme`.

## Базовый блок на каждой странице

Это правило для **всех** страниц сайта, включая будущие: шапка страницы
всегда начинается с того же блока «логотип + поиск» (`#menuButtonContainer`
→ `.menu-trigger-row`), что и главная. Отдельных кнопок «На главную»,
«Домой» и т.п. быть не должно.

- На главной логотип — кнопка, открывающая каталог.
- На остальных страницах логотип — ссылка `data-back` на родительскую
  страницу. Клик всегда ведёт по её `href` (SPA-переход с `pushState`) и
  автоматически открывает каталог на главной — независимо от истории
  посещений. Исключение — отдельная кнопка «Назад к заметкам» внутри
  сгенерированной заметки `wiki/zqwy`: она возвращает к списку заметок,
  потому что логотип ведёт на главную, а не в этот список.
- Поиск работает так же (растёт при вводе); на страницах без области
  результатов запрос уходит на главную как `?q=...`, и главная сразу
  выполняет его.
- Для подключения на новой странице нужны те же `#siteSearch` /
  `#siteSearchInput`, `#menuButtonContainer`, `scripts/menu.js` и
  `scripts/transition.js`, плюс стили `menu.css`, `menu_logo.css`,
  `base.css` и `player.css`. Подключение `scripts/player.js` и
  `styles/player.css` обязательно: только так плеер останется постоянным
  на всех разделах сайта.

## Поиск

Поиск отправляется из единственного поля (Enter); отдельной кнопки
«Найти» нет. Результаты выводятся под заголовком на главной странице.
Если меню было открыто, после отправки оно закрывается, а результаты
прокручиваются в видимую область. На второстепенной странице запрос
уходит на главную через SPA-переход (`/?q=...`) и выполняется сразу.

- **Общий поиск сайта по Ctrl/Cmd+F.** Вместо браузерного «Найти» сочетание
  переводит фокус в то же поле `#siteSearchInput`, выделяет текущий запрос и при
  необходимости закрывает меню. У поля есть скрытая подпись и подсказка
  «Общий поиск сайта (Ctrl+F)»; видимый плейсхолер остаётся коротким
  («Поиск»), поэтому компактная ширина в покое и геометрия меню не меняются.
- **Поиск также ищет по тексту открытой страницы.** Видимые текстовые блоки
  `.page-content` прогоняются через те же правила синонимов и фраз, что и
  индекс; совпадения выводятся первыми и при клике плавно прокручиваются к
  месту на странице с краткой подсветкой. На страницах без области результатов
  (например, внутри заметки) найденное слово подсвечивается сразу, без ухода
  на главную; если совпадения нет, запрос уходит на главную как раньше. Если
  индекс недоступен, поиск по странице продолжает работать.
- Поиск находит **все похожие слова**, а не только первое совпадение: синонимы
  прослеживаются на несколько шагов (RU → EN → другое написание), а токены
  сравниваются не только точным вхождением, но и по началу слова и с
  ограниченным расстоянием Левенштейна (опечатки и небольшие формы слова).
  Каждое найденное слово оборачивается в `<mark class="zqwy-search-word">` и
  остаётся подсвеченным до следующего запроса; блок вокруг активного слова
  получает короткую подсветку. Повторное нажатие **Enter** в поле поиска, пока
  запрос не изменён, переходит к следующему слову, **Shift+Enter** — к
  предыдущему; счётчик «Совпадение N из M» показывает текущую позицию. Клик по
  результату на странице переводит к соответствующему слову. В результатах
  показывается фрагмент текста, чтобы разные совпадения под одним заголовком
  были различимы.
- Пустой запрос (Enter с пустым полем) открывает каталог, а не показывает
  ошибку. Сообщение «Ничего не найдено. Попробуйте слово на другом языке.»
  выравнивается по центру, как первый абзац главной. Переключатель RU/EN в
  настройках меняет только язык интерфейса и системных сообщений; сам поиск
  остаётся двуязычным.

Источник — `./data/search-index.json`. Сейчас это **413 записей**
(11 страниц, 55 ссылок, 10 игр, 40 релизов, 296 треков, 1 заметка) и **51 группа синонимов**.
Формат: `{ generatedAt, synonyms, phrases, items: [{title, path, text, tags,
category, type, keywords}] }`; у заметок в `text` лежит полный markdown-текст
с явными `<br>` на мягких переносах.

- **Поиск по ключевым словам и словам на другом языке.** В `search-synonyms.json`
  хранятся группы эквивалентных слов RU/EN: `tiktok / тикток`,
  `youtube / ютуб`, `spotify / спотифай`, `music / музыка`,
  `album / альбом`, `track / трек / песня` и др. Запрос `тикток` находит
  те же ссылки, что и `tiktok` (и наоборот). Сопоставление
  регистронезависимое, `ё` приравнивается к `е`.
- **Фразовые алиасы внутри предложения.** В индексе есть отдельное поле
  `phrases`: `vojna a mier`, `vojna i mir`, `война и мир`, `войну и мир`,
  `war and peace`. Сначала выполняется исходный запрос; если он не дал
  результатов, `scripts/menu.js` ищет известную фразу внутри всего введённого
  текста. Поэтому `Vojna a mier`, `война и мир`, `Войну и мир` и даже
  `я ищу войну и мир в предложении` находят трек `Vojna a mier` (а `Войну и
  мир` — ещё и заметку `folk`). Фразы не добавляются в `synonyms`: счётчик
  групп остаётся 51.
- **Поиск треков и альбомов на RU и EN.** По названию трека (`Lilith`) находится
  результат типа `track` со ссылкой вида
  `./music/?album=axs&track=0#axs`. Такой результат открывает раздел
  `music` через SPA-переход, выбирает альбом и сразу запускает трек.
  Русский запрос тоже работает: `лилит` находится по транслитерации,
  `агония` — по словарю переводов (`Agonia`), `лес` — по переводу `forest`.
  `scripts/build_search_index.mjs` добавляет каждому треку и релизу
  ключевые слова-переводы и кириллическую транслитерацию, поэтому
  английский и русский запросы приводят к одним и тем же результатам.
- У каждого результата есть иконка типа (`🔗` ссылка, `♪` трек, `▣`
  альбом, `🎮` игра, `▤` страница).
- Индекс пересоздаётся автоматически при сборке; чтобы добавить пару
  слов, достаточно поправить `dev/data/search-synonyms.json` и запустить
  `npm run index` (или `npm run build`).

Поиск требует HTTP-сервера: при открытии файла напрямую `fetch` не сможет
прочитать JSON.

`<svg><use href="../assets/icons/links.svg#…"></use></svg>` берёт символы из

монограммы-заглушки для недостающих брендов). Иконки наследуют `currentColor`,
поэтому работают в обеих темах; это first-party рантайм-ассеты, а не
`src/icons/`.

### Реакция карточек на курсор

`scripts/hover-glow.js` даёт каждой карточке свой акцентный цвет и следит за
курсором. При наведении на `spotify` карточка становится зеленоватой, а
радиальное свечение и подсвеченная 1px рамка следуют за мышью (`--mx` / `--my`).
У `youtube` красный, у `tiktok` розовый, у `sumbit_hub` фиолетовый, у Duolingo
зелёный. Цвета задаются шаблонами в `hover-glow.js`, а сама
графика — псевдоэлементами в `base.css`. Обычное
состояние остаётся чёрно-белым, подсветка появляется только при `:hover` /
`:focus-visible`. Подсветка стала мягче: радиальная заливка — `0.2`, рамка —
`0.4`, фокусная рамка — `0.24` вместо прежних `0.3 / 0.7 / 0.32`. У выделенных
с клавиатуры карточек и кнопок разделов рамка становится полупрозрачной
(`--focus-border`) вместо резкой белой, а родной браузерный outline отключён —
фокус всё ещё виден, но не бросается в глаза. При `prefers-reduced-motion`
отключаются только трансформации и переходы, сама подсветка работает.

Тот же механизм работает и в музыке: `hover-glow.js` следит за указателем на
`.music-track`, а `music.css` рисует вокруг строки трека радиальный фон и
1px рамку, которые следуют за курсором. Акцент у треков нейтральный
(белый/чёрный в зависимости от темы), поэтому чёрно-белый характер каталога
сохраняется.

## Музыка и универсальный плеер

`dev/music/index.html` — страница `/music/` с каталогом релизов.
Сам плеер живёт **глобально**: `scripts/player.js` внедряет панель в
`<body>` вне `.page-content`, поэтому она не уничтожается при SPA-переходах
и не прерывает воспроизведение при переходе в `links` или любой другой
раздел. Один и тот же экземпляр панели используется на всех страницах.

- Каталог строится из `src/tracks/`: один релиз = одна папка верхнего
  уровня, треки — все аудиофайлы внутри на любой глубине. Служебные
  каталоги (`Media`, `loops`, `AutoSaves`, `worked`, `projects_rpp`,
  `orig_*`) и неаудиофайлы отфильтровываются. Сейчас: **40 релизов,
  296 треков**. Генератор один раз измеряет длительность каждого трека
  через `ffprobe` и пишет поле `duration`, поэтому `mm:ss` в строке трека
  видно сразу, без ожидания воспроизведения.
- Категория **«музыка»** в меню раскрывается на два отдельных сервиса:
  **«плеер»** (`/music/`, каталог релизов) и **«радио»** (`/radio/`, отдельная страница
  и `scripts/radio.js`). Радио — круглосуточный эфир без отдельного потока/сервера:
  он использует тот же глобальный плеер и каталог, но не живёт больше внутри страницы
  плеера. Программа представляет собой **одну непрерывную последовательность треков**
  на полные сутки от фиксированной точки `2020-01-01T00:00:00Z`: треки идут строго
  один за другим, после полуночи начинается следующий цикл. Порядок детерминирован
  FNV-хэшем от id трека (`album id + путь`) и номера цикла, поэтому `generatedAt`,
  номер сборки, перестановка релизов и обновление сайта **не сдвигают эфир**.
  На странице показываются текущий блок, трек, следующий трек и прогресс; переключать,
  перематывать, ставить в очередь или выбирать треки вручную нельзя — пока радио
  активно, плеер заблокирован API `setProgramLock(true)`. При уходе с `/radio/`
  блокировка снимается, а эфир останавливается.
- У каждой строки трека есть кнопка «+» **«Добавить в очередь»**. Очередь —
  явный список «дальше играть»: она живёт в `window.zqwyPlayer`, показывается
  кнопкой в панели, сохраняется в `zqwy.player.state.v1`, а `next()` расходует
  её раньше обычного порядка альбома. Добавленные треки помечаются в списке,
  их можно убрать или очистить очередь целиком; API — `enqueue`,
  `removeFromQueue`, `clearQueue`, `getQueue`, `openQueue`, `closeQueue`.
- Клик по обложке релиза (в шапке выбранного альбома) открывает отдельный
  анимированный лайтбокс поверх плеера (`#coverLightbox`, `z-index: 1000002`):
  пиксельные обложки остаются без сглаживания, закрывают его крестик, фон,
  `Esc` и переход на другую страницу. Это не полноэкранный режим релизов —
  последний по-прежнему вызывается кнопкой «Релизы на весь экран».
- Слева — релизы с фильтром, счётчиком и переключателем из трёх видов:
  **список** (компактные строки высотой почти только с текст), **карточки**
  (обложка 42 px, название и число треков) и **крупно** (контейнер с обложкой
  96 px и увеличенными отступами). Выбор сохраняется в `zqwy.music.view.v1`
  (`list`, `cards` или `large`). Справа — треки выбранного релиза. Выбор
  релиза отражается в хэше (`#album-id`), так что страницу можно открыть
  сразу на нужном альбоме. `scripts/music.js` отвечает только за каталог
  и передаёт воспроизведение глобальному плееру через `window.zqwyPlayer`.
  Релизы и треки появляются со ступенчатой анимацией (`--i` +
  `music-item-in`, `prefers-reduced-motion` уважается).
- При смене вида и при входе/выходе из полноэкранного режима размеры
  контейнеров анимируются: CSS-переходы меняют ширины колонок, сетку,
  отступы и размер обложки, а `scripts/music.js` дополнительно запоминает
  старые прямоугольники релизов и проигрывает FLIP-анимацию перехода
  (`Element.animate`, 240 ms, та же кривая `cubic-bezier(0.22, 1, 0.36, 1)`).
  Панель инструментов и счётчик релизов имеют собственный слой и фон, а список
  релизов — изолирующий `z-index`, поэтому во время FLIP-анимации счётчик
  «40 релизов · 296 треков» не перекрывается треками.
  При `prefers-reduced-motion` анимация отключается. Полоса прокрутки списка
  релизов отодвинута на 10 px от правого края сайдбара; в полноэкранном
  режиме отступ сбрасывается.
- Кнопка **«Релизы на весь экран»** рядом с переключателем вида включает
  полноэкранный режим: заголовок раздела и список треков скрываются, а релизы
  раскладываются сеткой на всю ширину. **Выбранный вид сохраняется**: таблица
  остаётся таблицей (одна колонка строк), карточки — карточками, а крупный
  вид показывает обложки 112 px. Выбор релиза, повторное нажатие или `Esc`
  возвращает обычный вид со списком треков.
- Ширина колонки релизов **измеряется по самому длинному видимому названию**
  (через `canvas` и реальный шрифт строки), а не задаётся константой. Короткие
  названия оставляют больше места трекам; границы — 170–340 px для списка,
  220–390 px для карточек и 300–480 px для крупного вида. В полноэкранном
  режиме измерение не нужно: сетка занимает всю ширину.
- В колонке номера активного трека вместо цифры появляется настоящая кнопка
  play/pause, точно отцентрированная по номеру. По клику она ставит текущий
  трек на паузу и снимает её **без перезапуска** (клик по другой строке
  начинает новый трек). Иконки play/pause плавно меняются через opacity +
  scale; `aria-label` и классы `is-active` / `is-playing` синхронизируются
  с состоянием плеера.
- Панель: обложка, название трека и релиза, play/pause, предыдущий/
  следующий, перемотка, громкость и mute, кнопка очереди, shuffle, повтор
  (`off → all → one`) и закрытие. Блок `.player-now` прижат к левому краю
  (`justify-self: start`), поэтому длинное название не сдвигает
  отцентрированные кнопки управления. Значок повтора — полноценный SVG-цикл,
  а не сломанный путь. Панель **выползает снизу вверх** за счёт
  `translateY(100% + 12px) → 0`, а её содержимое догоняет её с небольшой
  задержкой; закрытие — обратная анимация. `prefers-reduced-motion`
  отключает движение.
- При переключении треков новый звук **плавно появляется**, а старый **плавно затухает** (fade-in → fade-out).
  Оба фейда включаются и выключаются **независимо** своими чекбоксами в «Настройках плеера» → «Поведение»;
  общий плавный переход между треками по-прежнему задаётся отдельным переключателем. Длительности
  настраиваются ползунками (0–3 с, шаг 50 мс): сначала «Появление», затем «Затухание», в том же
  порядке подписана и мини-визуализация кривых. По умолчанию: появление 0,5 с, затухание 0,7 с.
  Минимальный 15 мс anti-click ramp сохраняется даже при выключенном fade-in, чтобы смена `src`
  не давала щелчка; он не является слышимым fade-in. Состояние обоих чекбоксов сохраняется в
  `zqwy.player.state.v1`, попадает в legacy-ключ и в ссылку «Поделиться настройками».
  Затухание идёт на временном `<audio>` через `GainNode` Web Audio (equal-power curve) — без
  ступенчатого изменения `volume` и без щелчка на смене `src`. Новый трек получает fade-in через
  основной `GainNode` на общем `<audio>` и подключается только после того, как копия старого уже реально играет,
  поэтому не возникает ни паузы тишины, ни наложения старого вступления на новый трек.
  Общий `<audio>`, все движки, Media Session и визуализаторы работают как раньше.
- Дисторшн, хорус, флейзер, дилей и реверб **запекаются в звуковую волну один раз**, а не живут
  в постоянном Web Audio-графе. Кручение ползунков и холстов остаётся потоковым: рендер
  запускается только после **10 секунд бездействия** (дебаунс увеличен с 400 мс), затем плеер
  декодирует исходник, прогоняет его через `OfflineAudioContext` и подменяет источник готовым
  WAV-blob. Пока рендер идёт, играет оригинал; после готовности трек перезагружается с той же
  позиции. Статус запекания показывается **в строке аудиоволны плеера**, а не в блоке эффектов.
  Во время воспроизведения нет ни live DSP, ни постоянно работающего LFO, ни пересборки
  реверб-импульса на каждом движении мыши — трек статичен. Кэш ключуется парой «исходник +
  подпись параметров» и ограничен шестью blob/четырьмя декодированными файлами. Новые эффекты
  оформлены так же, как старые: enable-чекбокс, интерактивный canvas, ползунки, подписи RU/EN,
  сохранение и передача в ссылке «Поделиться настройками». После перезагрузки чекбоксы и звук
  берутся из одного и того же сохранённого состояния, поэтому визуально выключенный эффект не
  может остаться включённым в звуке.
- Рядом с аудиоволной есть кнопки **«Сохранить ремикс»** и **«Загрузить ремикс»**. Первая
  скачивает текущий эффективный источник (после запекания — WAV-blob); вторая загружает файл
  через `URL.createObjectURL` и передаёт его глобальному плееру как новый трек. Исходные
  файлы в `src/tracks/` никогда не перезаписываются, blob предыдущего ремикса освобождается.
- Эквалайзер перенесён в раздел **«Эффекты»** настроек плеера: он теперь находится после
  effect-панелей, перед лимитером. Визуализация fade-конверта стала прозрачнее: при выключенном
  появлении или затухании весь соответствующий участок кривой, а не только точка-ручка,
  рисуется тусклым пунктиром с пометкой «выкл».
- В «Настройках плеера» → «Поведение» есть переключатель **«Пропускать начальную тишину автоматически»**.
  Вместо фиксированного смещения плеер один раз декодирует файл, измеряет
  короткие RMS-окна и переходит только к первому устойчивому звуку после
  настоящей начальной тишины; музыка, начинающаяся сразу, не пропускается.
  Порог тишины (по умолчанию
  −38 дБ) и максимальную длину интро (45 с) можно настроить там же. Если
  анализ недоступен или настоящей тишины нет, трек начинается естественно —
  без угадывания и обрезания музыки. Сохранённая позиция трека всегда имеет приоритет, поэтому продолжение с того
  места не ломается. Все подписи плеера, включая настройки, переводятся вместе
  с сайтом (RU/EN).
- Следующий трек **предзагружается** в скрытый `<audio>` через 300 мс после старта текущего
  (учтены очередь, shuffle и повтор), поэтому смена трека не выглядит как ожидание сети.
  Во время загрузки в строке плеера показываются анимация и **процент**: WaveSurfer отдаёт
  прогресс событием `loading`, остальные движки используют `buffered`/`readyState` общего
  `<audio>`. Индикатор лежит над строкой перемотки и виден и у движков со своим интерфейсом.
- Поддерживается Media Session API: управление с клавиатуры/медиакнопок
  и метаданные трека в системном интерфейсе.
- Горячие клавиши (когда фокус не в поле ввода): `Space` — play/pause,
  `←/→` — перемотка на 5 с, `M` — mute.
- **`data-player-settings-mount`**: настройки плеера дублируются в
  раскрывающемся блоке боковой панели `music` и в поповере панели
  (кнопка-шестерня). Настройки сохраняются site-wide в
  `zqwy.player.state.v1` (старые ключи `zqwy.player.settings.v1` и
  `zqwy.player.album.v1` по-прежнему пишутся/читаются для совместимости).
  Тема — общий ключ `zqwy.site.settings.v1`.
- Кнопка **«Поделиться настройками»** в настройках плеера копирует ссылку на
  `/music/` с альбомом, треком и точным таймкодом:
  `?album=<id>&track=<n>&t=<секунды>#<id>` плюс `?player=<base64url JSON>` с
  настройками плеера (движок, формат, поведение, скорость, эквалайзер,
  эффекты и лимитер). Очередь и чужие локальные данные не передаются.
  При открытии ссылки `scripts/music.js` выбирает трек и запускает его с
  заданного таймкода, а `scripts/player.js` применяет и сохраняет настройки;
  служебные параметры `player`, `album`, `track` и `t` убираются из адреса.
  Если буфер обмена недоступен, ссылка показывается в поле для ручного
  копирования. Ссылка работает и через SPA-переходы сайта.
- Рядом с шестерёнкой есть кнопка «Интерфейс движка»: она показывает панель
  с реальными элементами управления выбранной библиотеки. Для Howler,
  MediaElement.js, AmplitudeJS, APlayer и jPlayer панель открывается
  автоматически; для HTML5, WaveSurfer, Peaks и Waviz она закрывается, чтобы
  не мешать волне. Кнопка, крестик и `Esc` закрывают панель вручную.

### Движки воспроизведения

Плеер настраиваемый: движок и формат аудио выбираются **компактными выпадающими списками**
(`<select data-player-setting="engine">` и `<select data-player-setting="format">`)
вместо прежних групп радио-кнопок (`.opus / .mp3 / .wav / .flac`).

У пяти библиотек, которые раньше работали «за кадром», теперь есть видимый
**«Интерфейс движка»** (`#engineLab`). Кнопка-монитор рядом с шестерёнкой
открывает панель вручную; при выборе Howler, MediaElement.js, AmplitudeJS,
APlayer или jPlayer она открывается сама (в том числе после восстановления
движка из `localStorage`). Закрыть её можно той же кнопкой, крестиком или
`Esc`. Стили APlayer, MediaElement.js и скин jPlayer подгружаются лениво из
`dev/vendor/`, AmplitudeJS оформлен в `styles/player.css`. Все интерфейсы
управляют тем же общим `<audio>`, поэтому очередь, Media Session и горячие
клавиши не ломаются.

- **HTML5 (браузер)** — запасной движок: включается, если JavaScript или API,
  нужные WaveSurfer, недоступны, а также если библиотека не загрузилась. При
  переключении на него панель интерфейса движка закрывается.
- **WaveSurfer.js (форма волны)** — движок по умолчанию, когда JavaScript
  работает (проверяются `Promise`, `fetch`, `requestAnimationFrame` и 2D-canvas).
  Подключается лениво из `dev/vendor/wavesurfer.min.js`; вместо ползунка
  перемотки показывается волновая форма. Перемотка курсором включена: клик и перетаскивание по волне
  меняют позицию (`interact`, `dragToSeek`, плюс событие `interaction`,
  продублированное на общий `<audio>`). Общий `<audio>` остаётся источником
  звука, поэтому Media Session и горячие клавиши работают в обоих режимах.
  Библиотека взята из
  `tiddlywiki-data/files/dev/scripts/containers/player/player_types/wavesurfer/`.
- **Peaks.js (форма волны)** — подключается лениво из
  `dev/vendor/peaks.min.js` (`peaks.js@3.1.0`, UMD-сборка). Волна рисуется в
  `zoomview`, данные декодируются через `webAudio: { audioContext }`, а
  перемотка идёт через тот же `<audio>`. При переключении темы цвета волны
  обновляются без пересоздания плеера.
- **Howler.js (живой сигнал)** — подключается лениво из
  `dev/vendor/howler.min.js` (`howler.js@2.2.4`). Howler управляет тем же общим
  `<audio>`: на время создания `Howl` его `_obtainHtml5Audio()` возвращает наш
  элемент. В панели движка `<canvas id="labAnalyser">` рисует реальный сигнал,
  который Howler отдаёт в Web Audio, и показывает его уровень в процентах.
  При выходе из движка обработчики снимаются с `<audio>`.
- **Waviz (визуализация)** — подключается лениво из `dev/vendor/waviz.min.js`
  (`waviz@1.0.0`, UMD-сборка). В строке волны появляется `<canvas>`, на котором
  Waviz рисует живую линию через Web Audio (`simpleLine`) во время
  воспроизведения и останавливается на паузе. `AudioContext` общий с Peaks,
  `MediaElementSource` для `<audio>` создаётся один раз и переиспользуется.
- **MediaElement.js (интерфейс)** — `dev/vendor/mediaelement-and-player.min.js`
  (`mediaelement@7.1.0`) + `dev/vendor/mediaelementplayer.min.css`. Библиотека
  один раз оборачивает общий `<audio>` настоящим `MediaElementPlayer`, а его
  контейнер `.mejs__container` с кнопками, прогрессом и громкостью переносится
  в `#labMediaElement`. Поэтому видны именно родные элементы управления
  MediaElement.js, а не пустая обёртка.
- **AmplitudeJS (интерфейс)** — `dev/vendor/amplitude.min.js`
  (`amplitudejs@5.3.2`). Разметка в `#engineLab` (`amplitude-play-pause`,
  `amplitude-current-time`, `amplitude-duration-time`, `amplitude-song-slider`,
  `amplitude-volume-slider`, `data-amplitude-song-info`) существует до вызова
  `Amplitude.init()`, поэтому библиотека привязывается к ней сама. Конфиг
  указывает на общий `<audio>`, а собственные обработчики Amplitude остаются
  на приватном элементе и не мешают очереди zqwy.
- **APlayer (интерфейс)** — `dev/vendor/aplayer.min.js` (`aplayer@1.10.1`) +
  `dev/vendor/aplayer.min.css`. Экземпляр создаётся прямо в `#labAPlayer` и
  показывает свою обложку, название, список и кнопки; на время конструктора
  `document.createElement('audio')` возвращает общий элемент, поэтому APlayer
  управляет именно им.
- **jPlayer (интерфейс)** — `dev/vendor/jquery.jplayer.min.js` (`jPlayer@2.9.2`)
  вместе с закреплённым `dev/vendor/jquery.min.js` (jQuery 2.2.4),
  `jplayer.blue.monday.min.css` и изображениями скина. В `#labJPlayer` лежит
  стандартная разметка jPlayer (`jp-play`, `jp-seek-bar`, `jp-volume-bar`,
  `jp-current-time`, `jp-duration`), а плагин получает общий `<audio>` тем же
  приёмом с `createElement`. jQuery и jPlayer загружаются лениво.

**Двойной клик по волне WaveSurfer** ставит трек на паузу, второй двойной
клик снимает её. Обработчик `dblclick` живёт на `#playerWaveform` и снимается
в `destroyWaveforms()` при смене движка или трека.

### Форматы аудиофайлов

В настройках плеера есть отдельный выпадающий список «Формат аудиофайла» с вариантами
`.opus`, `.mp3`, `.wav`, `.flac`. `scripts/build_music_catalog.mjs` сохраняет
для каждого трека карту `formats` с путями ко всем реально существующим
версиям файла. Плеер выбирает выбранный формат через `resolveTrackPath()`,
а если такого файла нет — откатывается к основному пути (сейчас в архиве
только `.opus`) и пишет об этом в строку статуса. Выбор сохраняется в
`zqwy.player.state.v1` и в старом `zqwy.player.settings.v1`.

В волновых режимах строка с таймингами и волной занимает всю ширину
панели, а кнопки управления отцентрированы по центру панели (равные боковые
колонки сетки). Надписи «Движок плеера: …» под волной больше нет — волна
занимает освободившееся место и стала выше (64 px). Ширина блока с названием
трека вычисляется из количества символов (`--title-chars` в `renderMetadata()`),
поэтому между названием и кнопками почти нет пустого пространства. Панель
плеера отображается поверх полноэкранного каталога (`z-index: 1000001`), а у
прокручиваемого содержимого каталога есть отступ снизу.
- Кнопка настроек панели — полноценная шестерёнка (сплошной SVG-путь с
  центральным отверстием), а не абстрактный значок. Настройки открываются и
  закрываются анимацией: поповер раскрывается **вниз от своего верхнего края**
  (`transform-origin: top right`, `translateY(-14px) → 0`), шестерёнка
  поворачивается на 90°; стрелка блока настроек в сайдбаре `music` тоже
  поворачивается.
  Переключение play/pause в панели анимировано так же, как в списке треков.
  Пользователи с `prefers-reduced-motion` видят всё без анимации.
- Дополнительно сохраняются: громкость, mute, shuffle, repeat,
  «играть следующий автоматически» и «запоминать позицию трека».
  Выбранный движок восстанавливается после перезагрузки любой страницы.

### Обложки

Оригиналы лежат **только** в
`/home/zqwy/smb/sda/content/category/photo/sound_cover/<album-id>/...` и
генератор их не трогает. `scripts/build_covers.py` (`npm run covers`) выбирает
для каждого релиза лучший исходник (сначала готовый `*_site.webp`, затем
`*cover*` в webp/jpg/png; баннеры и файлы из `tracks/` пропускаются),
уменьшает его до 512 px по длинной стороне и пишет в
`src/covers/<album-id>/<album-id>.webp` — в `src/covers/` остаются только
лёгкие WebP-файлы. Повторный запуск пропускает неизменённые исходники
(контроль по размеру и mtime через `scripts/.covers-manifest.json`), `--force`
пересоздаёт всё. Пиксельные обложки определяются по числу цветов и сохраняются
lossless без сглаживания; остальные — lossy WebP quality 78.

Сайт берёт обложки из `src/covers/<album-id>/`; если обложки нет, показывается
буква релиза. Для пиксельных обложек в CSS включён `image-rendering: pixelated`
(без сглаживания при масштабировании). При первом открытии страница остаётся
сверху: прокрутка к списку треков происходит только после явного выбора релиза.

У плеера есть публичный API `window.zqwyPlayer` (`playTrack`, `setContext`,
`toggle`, `play`, `pause`, `next`, `previous`, `stop`, `seek`, `seekProgram`,
`setProgramLock`, `getState`, `setEngine`, `setFormat`, `openSettings`, `enqueue`,
`removeFromQueue`, `clearQueue`, `getQueue`, `openQueue`, `closeQueue`, `on`)
и событие `zqwy:playerstate`. Идея «один плеер на все
треки» взята из `tiddlywiki-data/files/dev/scripts/containers/player/`.

## Переходы между страницами

`dev/scripts/transition.js` подключен на главной, `links` и `music`.
Это SPA-переход без перезагрузки: запрашивается HTML нужной страницы,
заменяется **только** `.page-content`, а логотип/поиск, тема и глобальный
плеер остаются на месте. Открытие разделов (`links`, `music`, `game` и т.д.)
использует **ту же анимацию, что и логотип при открытии каталога**:
`opacity + translateY(24px) scale(.985)`, `0.42s cubic-bezier(.4, 0, .2, 1)`.
Текущая страница уходит этим же движением в обратную сторону
(`.page-leaving`), новая появляется с `.page-enter` — переходы выглядят
монолитно и вперёд, и назад. `prefers-reduced-motion` отключает движение.

- После подмены содержимого загружаются стили и скрипты, специфичные для
  новой страницы (`music.css`/`links.css`, `music.js`), а затем отправляется
  событие `zqwy:pagechange`. Скрипты слушают его и переинициализируются;
  слушатели в `menu.js` и `music.js` делегированы на `document`, поэтому
  не «зависают» на удалённом DOM.
- Перед первым переходом относительные `href`/`src` подключаемых файлов
  превращаются в абсолютные: `pushState` меняет базовый URL документа, и
  иначе стили/скрипты стали бы резолвиться относительно нового пути.
- `window.zqwyNavigate(href)` — публичный вспомогательный метод для поиска
  на страницах без области результатов.
- Внешние ссылки, новые вкладки, скачивания и чистые хэш-якоря не
  перехватываются. При `prefers-reduced-motion: reduce` анимации
  полностью отключены, а SPA-переход становится мгновенным.
- Логотип на второстепенных страницах (`data-back`) больше не использует
  `history.back()`: он всегда делает `pushState` на свой `href` и после
  `zqwy:pagechange` программно нажимает главную кнопку-логотип, чтобы каталог
  открылся сам. Браузерные Back/Forward по-прежнему идут через тот же
  переход, но уже без `popstate`-гонки с содержимым.
- `transition.js` хранит отдельно `renderedUrl` — URL, который реально
  показан на экране. Один клик по логотипу сразу меняет и адрес, и содержимое,
  а каталог уже открыт на месте.
- Воспроизведение при любом таком переходе продолжается: плеер живёт
  вне `.page-content`.

  `vendor/amplitude.min.js`, `vendor/aplayer.min.js`, `vendor/jquery.min.js`,

  `vendor/jplayer.blue.monday.min.css`, `vendor/image/jplayer.blue.monday.*`

  (создаётся `npm run index` / `npm run build`).

- `data/music-catalog.json` — сгенерированный каталог музыки с длительностями

  сохраняются как явные `<br>`, а индекс поиска хранит полный текст заметки.

## Локальный просмотр

```bash
cd /home/zqwy/smb/sda/apps/zqwy

npm run serve:dev    # рабочая версия: сервер от корня проекта, открыть /dev/
npm run serve:dist   # собранная версия (после npm run build): корень — dist/
```

Обе команды поднимают `http://localhost:8080/`.

Важно: сервер для `dev/` запускается **от корня проекта**, а не изнутри
`dev/`. Иначе плеер не сможет прочитать `data/music-catalog.json` и аудио
из `src/tracks/` (относительные пути вида `../../src/...`). Адреса:
`http://localhost:8080/dev/` для рабочей версии и
`http://localhost:8080/music/`, `http://localhost:8080/links/` для
собранной. Старый вариант `python3 -m http.server 8080 --directory dev`
для музыки больше не подходит.

## Docker

Контейнер **не содержит запечённую копию сайта**. `docker-compose.yaml`
монтирует host-каталог `./dist` в контейнер как `/app/dist` только для чтения,
а `serve` отдаёт именно его. `Dockerfile` теперь только runtime-образ с `serve`.

Обновление сайта после правок в `dev/`, `scripts/` или `src/`:

```bash
cd /home/zqwy/smb/sda/apps/zqwy
npm run build          # пересобрать dist/ на хосте
```

Пересобирать образ и **пересоздавать/перезапускать контейнер не нужно**:
`serve` отдаёт файлы прямо из смонтированного `/app/dist`, поэтому после сборки
достаточно обновить страницу в браузере (при агрессивном кэше — жёсткое
обновление, `Ctrl+F5`).

`scripts/build_dist.sh` очищает содержимое `dist/`, но не удаляет сам каталог.
Это важно: если удалить и создать `dist/` заново, bind mount контейнера
сломается (внутри останется старая точка монтирования) и тогда действительно
придётся делать `docker compose up -d --force-recreate`. Если когда-то собрали
`dist/` старой версией скрипта, один раз пересоздайте контейнер после сборки:

```bash
docker compose up -d --force-recreate
```

Пересобирать образ нужно только при изменении самого `Dockerfile`. После
изменения `docker-compose.yaml` достаточно пересоздать контейнер:

```bash
docker compose up -d            # применить новый compose-файл
docker compose up -d --build    # только если менялся Dockerfile
```

Важно: `./dist` в `volumes` — это путь на машине, где запущен Docker-демон.
Если демон удалённый, сборка должна находиться именно там. Для обычного
локального Docker достаточно `npm run build` в этом каталоге.
