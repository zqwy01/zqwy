# Музыкальный плеер (`dev/scripts/music/player/`)

Раньше весь плеер был в одном `dev/scripts/player.js` (почти 6 тыс. строк).
Теперь этот файл — тонкая точка входа:

```html
<script src="../scripts/player.js" type="module"></script>
```

`player.js` импортирует `music/player/index.js`, который собирает модули и
запускает плеер. Используются **нативные ES-модули без бандлера**: только
относительные импорты с расширением `.js`, поэтому всё работает и из `dev/`,
и из `dist/`, и на GitHub Pages с подпутью репозитория.

## Совместимость

Сохранены все внешние договорённости:

- `window.zqwyPlayer` с тем же набором методов;
- событие `zqwy:playerstate`;
- ключи `localStorage` `zqwy.player.state.v1`, `zqwy.player.settings.v1`,
  `zqwy.player.album.v1`;
- событие `zqwy:languagechange` и `data-player-i18n` атрибуты;
- путь `scripts/player.js` во всех HTML и генераторе заметок.

`transition.js` при SPA-переходах копирует `type="module"` с исходного тега,
иначе браузер попытался бы выполнить модуль как обычный скрипт. Сам модуль
выполняется один раз: `window.zqwyPlayer` и DOM панели переживают навигацию.

## Карта файлов

| Файл / каталог | Что внутри |
| --- | --- |
| `context.js` | общее состояние и константы (бывшие верхнеуровневые `const`/`let`); пути вендора и сайта через `import.meta.url` |
| `lazy.js` | динамическая подгрузка тяжёлых частей и заглушки на время загрузки |
| `index.js` | сборка модулей, публичный API, `restore()` |
| `events.js` | обработчики событий панели и страницы |
| `i18n.js` | строки RU/EN и переключение языка |
| `init.js`, `persistence.js`, `share.js`, `intro.js` | восстановление состояния, `localStorage`, ссылки, анализ начала трека |
| `ui/` | разметка панели, настройки, очередь, эквалайзер, кроссфейд, FX, limiter |
| `playback/` | воспроизведение, фейды, очередь, скорость |
| `audio/` | граф Web Audio, EQ, limiter, эффекты, энкодеры |
| `engines/`, `engine/` | девять аудиодвижков, загрузка вендорных скриптов, выбор движка по умолчанию |
| `remix.js` | создание/сохранение/загрузка ремиксов |

## Мягкая подгрузка

При старте загружается только то, что нужно панели и обычному воспроизведению.
Следующие группы подключаются динамически при первом использовании:

- `ui/fx.js` — при первом открытии панели настроек (до этого рисовать нечего);
- `engines/*.js` — при первом воспроизведении не-HTML5 движком;
- `audio/encoders/*.js` — при первом рендере эффектов или сохранении ремикса;
- `remix.js` — при нажатии кнопки ремикса.

`lazy.js` ставит заглушки, которые перенаправляют вызов в динамически
загруженный модуль; после установки реальной функции вызов идёт напрямую через
общий контекст `P`. Повторная загрузка группы не происходит.

## Сборка

`npm run build` копирует `dev/` в `dist/` и минифицирует каждый `.js`
отдельно, включая модули. Terser сохраняет `import`/`export` и `import()`,
поэтому дополнительных шагов сборки не требуется.

> Новые файлы лежат внутри игнорируемого `dev/`, как и остальные исходники.
> Для коммита их нужно добавить явно: `git add -f dev/scripts/music/player`.
